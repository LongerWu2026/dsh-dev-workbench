# 智能工作台 · DSH Dev Workbench

DeepSeek Harness 原生插件，把 AI 助手、消息跟进、研发任务、多 AI 对话、开发调试和知识检索放在同一个工作入口。复用 Harness 已配置的模型、会话和工具，从日常沟通中整理事项，带着工程与来源上下文继续处理，再把确认过的结论沉淀为知识。

- **AI 助手**：在统一会话中读取消息识别、资讯、知识和事项上下文，结合规则与 AI 处理操作，保留进度、结果及确认回执。
- **办公跟进**：今日简报、待办与待回复、云之家会话阅读、持续消息识别和日报周报。
- **研发协作**：Linky 工作项、本地工程、专属 Harness 会话、测试与独立审查。
- **分析与复用**：多 AI 统一提问、开发工具与数据查询、全局本地搜索，以及按空间和项目隔离的本地知识检索。

## 安装与升级

需要已安装的 DeepSeek Harness；命令行安装需要 Node.js **≥22.19.0** 和可用的 `dsh` 命令。插件名称为 `dsh-dev-workbench`，界面名称为「智能工作台」。

### 从插件市场安装

在 **dshmarket** 中搜索 `dsh-dev-workbench` 或「智能工作台」，进入详情安装或升级。市场共享目录更新可能晚于 GitHub 和 npm；中国大陆线路还取决于目录包及镜像同步。暂时搜不到或版本较旧时，可使用下面的安装方式。

### 通过 npm 安装

通过 npm 安装 registry 已发布的版本；版本列表见 [npm 包页面](https://www.npmjs.com/package/dsh-dev-workbench?activeTab=versions)。安装本次 GitHub 版本请使用下一节的预构建包。

```sh
dsh plugin --profile desktop add dsh-dev-workbench
```

将 `desktop` 替换为实际宿主使用的 profile。使用指定版本便于核对安装结果；桌面端也可使用应用自己的插件管理入口。

### 下载预构建包

从 [Releases](https://github.com/LongerWu2026/dsh-dev-workbench/releases) 下载 `dsh-dev-workbench-<版本>.tgz`，或直接安装：

```sh
dsh plugin --profile desktop add https://github.com/LongerWu2026/dsh-dev-workbench/releases/download/v0.4.10/dsh-dev-workbench-0.4.10.tgz
```

升级后按宿主机制重载插件组件或重启 Harness，再打开侧栏「智能工作台」。只刷新页面不会重新注册新增 Host 接口；遇到 `/api/workbench/...` 返回 404，先重载插件组件。升级前建议备份工作台数据，位置见下文。

## 首次使用

1. 打开「更多 → 连接与设置」，按需要配置连接器、项目和 AI。AI 主开关、自动登记及普通定时运行分别配置，新安装默认关闭；AI 使用宿主已配置模型及其用量。
2. 需要消息跟进时，在云之家连接器中点击「安装」和「登录授权」，在官方浏览器页面完成授权，再点击「重新检测」。连接成功后开始同步和提取；无需为 CLI 安装再次重启 Harness。
3. 在「今日简报」查看待办、待回复、日程与 AI 动态；点击「刷新全部内容」同步消息、日历和资讯，待办与待回复也可单独刷新。打开进度查看各阶段、识别数量及失败原因；进入来源详情核对消息后处理。
4. 打开顶部「AI 助手」，选择消息识别、AI 资讯、知识助手或已有工作会话。也可从单条待办、待回复或研发事项进入，继续对应上下文；添加资料和切换会话不会自动发送。
5. 需要研发辅助时，进入「研发任务」连接 Linky，选择本人工作项和工程，再确认测试命令。需要多 AI 问答时，进入「多 AI 对话」，在各厂商内嵌官网完成登录并选择发送对象。

各模块可独立使用；使用工具箱不要求先连接云之家或 Linky。窄窗口放不下的导航入口自动收进「更多」。

### AI 助手与办公工具

顶部「AI 助手」提供完整聊天页：消息识别、AI 资讯和知识助手有固定系统入口；待办、待回复、研发事项及自由对话按真实对象关联独立会话。会话支持搜索、置顶、历史选择及折叠，切换时保留各自草稿。打开、刷新或恢复历史只读取已有记录，首次发送或明确新建时才按需创建原生 Harness 会话。

- **上下文连续**：单条事项进入对应会话，默认恢复原绑定；展示事项来源、原生会话和工作区，研发主会话与审查会话分别管理。
- **结果可追溯**：消息识别和资讯时间线关联真实后台输入、结果、错误及持久作业；已提取的待办、待回复可以查看来源并回到原事项修正。
- **指令与确认**：明确、单一的常用操作优先由规则处理，其他请求交给 AI；卡片区分识别来源、执行结果和失败原因。发送回复、知识修改或删除等操作沿用目标预览和确认约束，重新理解指令不会重复执行旧操作。
- **附件与引用**：可选择、拖放或粘贴资料，发送前预览、移除或重试；引用事项最多 8 项。选择附件只更新草稿，点击发送后才通过当前原生会话上传。文件可读性和图片理解取决于宿主服务及模型能力，失败保留草稿。
- **办公主题**：从助手工具中选择日报、周报、批量回复草稿或待办方案；相同主题可恢复既有成果，查看和采纳草稿不会自动对外发送。原「智能办公」入口转入助手，旧记录保留。

原生会话、附件和身份能力依赖宿主实际提供的服务；不可用时显示原因。升级后须重载插件 Host 和客户端，才能使用新增接口。详见[AI 助手介绍](docs/ASSISTANT-HUB-2026-11-01.md)、[附件与引用](docs/ASSISTANT-ATTACHMENTS-IDENTITY-2026-11-01.md)、[事项与原生会话绑定](docs/ASSISTANT-NATIVE-BINDING-2026-11-01.md)和[办公主题](docs/ASSISTANT-COMPACT-WORKSPACE-2026-11-01.md)。

助手回复、多 AI 回答和助手设置预览使用内置的 Lulu 头像；本人头像沿用宿主配置。

### 会话运行与后台模型

助手目录与会话内容分别加载，单个请求失败可局部重试；切换会话保留草稿和阅读位置。用户原话与事项引用分别呈现，工具调用进度与最终回答分开展示。运行中的会话提供「停止」，收到取消确认后继续核对真实终态；连续作业暂停会跨重启保留，明确继续后才处理未完成项。已完成操作和历史结果继续保留。

在「连接与设置 → 后台任务模型」可分别选择消息识别与资讯摘要模型，或沿用会话模型。保存设置不启动任务，新选择从下一轮生效；目录来自宿主已配置的服务商，不另行保存模型凭据，也不修改宿主默认模型。能力依赖当前宿主公开接口，不可用时显示具体提示。详见[停止与暂停](docs/ASSISTANT-STOP-2026-11-04.md)、[后台模型](docs/BACKGROUND-MODELS-2026-11-04.md)和[局部加载](docs/ASSISTANT-PARTIAL-LOADING-2026-11-04.md)。

### 消息提取、待办与回复

消息按组织、账号、会话和原消息去重，保留来源及北京时间。聚焦未读消息、@本人、@全员及明确关联已有事项的跟进，普通已读聊天不会全量交给 AI。只采集和处理插件安装日期（北京时间）起的消息；升级、恢复与导入保留本机安装日期。

私聊未读先进入收件箱和识别队列，AI 明确需要回复后才登记回复义务，具体业务事项生成待办；群消息需要结构化 @本人或 @全员，并经 AI 判断存在对应义务。已读、确认收到和实际完成是不同状态，聊天不会自动完成或取消待办，人工确认字段受到保护。首页聚合存在明确关联的事项，完成待办和处理回复仍分别操作。

提取采用持久化队列：每批最多 50 条，点击一次持续处理，显示累计、剩余、失败及自动重试时间。临时失败按规则恢复，达到上限则明确暂停；重启恢复进度，成功内容不重复识别。普通自动同步在北京时间 **09:00–21:00 每五分钟**运行，包含 21:00；手动同步不受此时段限制。后台任务依赖 Harness 进程运行。

人工回复先编辑、核对并确认发送，生成、保存和复制草稿不会发送消息。可选的「忙碌自动回复」默认关闭：主动开启后，仅对本次忙碌期间的新未读私聊发送一次告知，每个会话每周期最多一次；成功告知后仍保留人工答复义务。该模式在 Harness 运行期间额外每分钟检查，关闭停止新告知，账号变化后需重新启用。详见[消息分流规则](docs/MESSAGE-ROUTING-RULES-2026-10-29.md)、[连续识别](docs/CONTINUOUS-ANALYSIS-2026-10-30.md)和[忙碌回复](docs/BUSY-PRIVATE-REPLY-2026-10-31.md)。

打开未读会话可在工作台阅读消息，上滚按批加载历史；完整展示未读后保存本地「工作台已读」。这不会清除云之家客户端红点，也不代表已回复或已完成待办。私聊本人真实答复可结清此前同轮问题，对方后续新问题仍独立保留；群聊仍要求明确引用原消息。详见[会话阅读](docs/CONVERSATION-READER-2026-11-02.md)、[回复分流](docs/REPLY-TRIAGE-2026-11-02.md)和[刷新说明](docs/WORKSPACE-REFRESH-2026-11-02.md)。

### Linky 研发任务

- 登录后查看本人需求、用户故事与缺陷，按空间、类型、状态筛选，打开完整描述并继续已有研发过程。
- 将工作项与本地工程、原生 Harness 工作区及专属会话关联。满足条件的干净 Git 根仓库可建立独立 worktree；普通目录或已有改动等情形使用所选目录，保留原有内容。
- 确认工程与测试命令后启动分析、开发、真实测试和独立 AI 审查。测试未配置、执行失败或模型异常会暂停；可补充要求并继续原会话。
- 绑定研发主会话可查询、修改当前 Linky 工作项标题、描述和业务状态，按真实流转及必填字段提交并回读核对；业务状态与本地开发执行状态分别展示，未核实的操作不自动重放。详见[工作项修改](docs/DEVELOPMENT-ISSUE-EDITING-2026-11-02.md)。
- 人工审查展示差异、测试退出码及审查意见。批准绑定当前代码内容，后续变化会使批准失效。批准与向 Linky 回写评论分别确认，评论回写不会代替代码提交、合并或发布。
- npm 包包含 `harness-linky` CLI，可将 Linky 的 Codex 协议入口适配到官方 Harness ACP；配置及权限边界见[实施说明](docs/LINKY-DEVELOPMENT-IMPLEMENTATION-2026-10-31.md)。

项目协作支持浏览本地文件、查看未提交差异、项目全文搜索、保存审阅进度和复制交接摘要。

研发目录支持列表与详情分栏，保留所选工作项、筛选及会话上下文，窄屏按可用空间展开。页面使用方式及工程选择见[研发任务说明](docs/DEVELOPMENT-UX-2026-10-31.md)。完整真实业务修复与回写仍需用户在实际工作项中验证，隔离测试不代表业务已完成。

### 全局搜索

点击顶部搜索图标或按 Cmd/Ctrl+K，在同一个弹窗中筛选并查找已保存的待办、知识、资讯和消息。可查看完整正文、打开原事项，或把当前结果交给对应助手会话继续处理。快速搜索只查本地记录，不把输入发送给企业 CLI 或互联网服务；联网搜索入口只预填可编辑指令，明确发送后才执行。详见[全局搜索说明](docs/GLOBAL-WORK-SEARCH-2026-11-03.md)。

快速搜索默认只查本地。明确选择「查询云之家」后，可在完整结果页按联系人、消息、文档、群聊等类型查询；查询使用已授权的云之家账号，类型切换不会自动发起查询。详见[云之家检索](docs/YUNZHIJIA-SEARCH-2026-11-04.md)。

### 多 AI 对话与历史

内嵌 Kimi、智谱清言、豆包、元宝和千问，ChatGPT 可选。统一输入问题，选择发送厂商，每轮通过厂商标签查看回答；各厂商保持自己的官网会话，新厂商不会自动继承其他厂商的历史上下文。

新增回答支持增量展示和 Markdown 排版，保留表格、代码语言及文件树结构；复制、导出和保存知识使用完整已采集正文。官网更新仍通过 DOM 观察获取，历史中已丢失的格式不会自动复原。各厂商的登录状态可单独检查，遇到登录或验证码由用户在官网完成。

支持选择、粘贴和拖入图片或文档，发送前预览和移除。每次最多 5 个附件，单文件 10 MB、合计 20 MB；历史仅保留附件元数据，刷新后需重选原文件。回答可保存、搜索、重命名、归档或放入本地回收站，选中回答可收藏到知识库。同步中断时可查看原对话，并粘贴保存未同步的回答。只有明确未提交的厂商才提供手动补发，提交结果不确定时不会自动重发。

登录、验证码、站点繁忙及附件格式受各厂商规则约束。**跨 Harness 重启的网页登录持久化需要另行适配宿主扩展，安装本插件不会自动修改桌面应用**；普通原版宿主不保证这一能力。详见[聊天与补发](docs/WEB-AI-CHAT-REDESIGN-2026-10-30.md)、[历史管理](docs/WEB-AI-LOCAL-HISTORY-2026-10-29.md)、[真实站点验证](docs/WEB-AI-LIVE-ACCEPTANCE-2026-10-30.md)及[可选 rc.5 宿主扩展](host-integration/rc5/README.md)。

### 本地知识检索与范围隔离

默认使用关键词检索；可在「知识空间 → 本地语义检索」中按需下载并启用本地模型。固定版本的 BGE-small-zh-v1.5 INT8 与 WASM 运行时合计约 47 MB，逐文件校验大小与 SHA-256，模型不捆绑进插件包。无需安装 Python 或 Ollama，下载完成后向量计算在本地 Worker 中执行，空闲时自动释放；模型未就绪或索引过多时回退关键词检索。

当前项目检索同项目与同空间公共资料，其他空间、其他项目不会自动纳入；个人通用知识需明确允许跨空间复用。已确认且有效的资料可自动增量索引，原文回读校验资料版本和引用范围。这里的范围隔离用于个人本地工作台，不提供多人服务的成员权限认证。PDF、Word 和图片未解析时不会被当作已入库正文。详见[本地 RAG 与知识空间](docs/LOCAL-KNOWLEDGE-RAG-2026-11-02.md)。

普通聊天的自动知识模式由模型按需查询已保存资料，不在每次发送前固定检索；实际查询后才显示知识依据。仅知识库模式仍先检索，未命中时不调用模型；关闭模式不自动查询。知识工具沿用当前会话的空间、项目和本轮引用范围，模型不能自行扩大范围。详见[按需检索](docs/KNOWLEDGE-ON-DEMAND-2026-11-04.md)。

可将已读云之家消息、助手定稿和资讯原文保存为笔记。保存前可编辑正文、标签及所属空间；默认仅保存笔记，勾选「用于 AI 回答」后才纳入该范围的知识检索。资讯原文不可用时仍可收藏链接。详见[多来源笔记](docs/KNOWLEDGE-CAPTURE-2026-11-04.md)。

### 开发工具与数据查询

工具箱按工具展示输入和结果，可搜索、筛选并在当前页面保留切换前的输入。JSON 支持格式化、树形查看和路径复制；Diff 支持文本和 JSON 结构对比；HTTP 调试支持导入基础 cURL、保存请求集合与环境、批量运行和校验响应断言。导入与 AI 生成只准备草稿。集合变量（如 `baseUrl`）保存在本地 `http-workspace.json`，文件使用私有权限，变量值以明文保存。另有 MCP Streamable HTTP 调试、日志筛选、正则、Cron、SQL 格式化、类型生成、YAML/CSV 转换等工具。AI 辅助需显式点击，沿用宿主助手。

数据连接支持 MySQL、PostgreSQL、Elasticsearch 和单节点 Redis：读取所选结构、生成查询并在用户点击后执行。SQL 使用语法树校验和只读事务，Redis 仅开放受限读取；建议配合只读账号使用。AI 生成只传数据库类型与所选结构元数据，不传连接密码、地址或业务行数据；生成的结构变更与回滚脚本仅供预览。SQL 查询每页可选 50、100 或 200 行，每页最多 1 MB，可继续翻页读取原查询结果。

每个连接目标保留独立的数据工作区，包括 SQL、对象选择、最近 AI 对话和查询结果；恢复后显示上次结果，执行查询仍需手动触发。工作区以本地私有权限文件保存，内容不加密，可在界面清除连接记忆。

数据连接密码默认仅驻留宿主内存。macOS 可选择「记住密码」，保存加密密文，密钥由系统钥匙串保管；取消勾选并保存可清除密文。HTTP/MCP 调试按用户操作联网，离线转换在本地执行。详见[工具箱介绍](docs/DEVELOPER-TOOLBOX-2026-10-31.md)、[数据连接说明](docs/DATA-TOOLS-2026-10-31.md)和[研发协作](docs/DEVELOPER-WORKFLOWS-2026-10-29.md)。

### 知识检索与工作汇总

回答和办公产物先保存为候选知识，经人工审核后参与默认检索。检索按项目、账号、有效期和归档状态过滤，默认采用本地中文分词、分块与 BM25 排序，回答携带实际使用的原文、版本及行号。可选远程 Embedding 需要 HTTPS，HTTP 仅允许本机回环地址；不安全地址会在发送凭据和正文前被阻断，并保留本地检索。

AI 助手的办公工具将工作记录组织为回复草稿、日报周报和待办方案，产物及执行状态可追踪。模型输出仍需人工核验，未命中资料时不会把未读取的链接当作依据。详见[知识检索与引用](docs/KNOWLEDGE-RETRIEVAL-IMPLEMENTATION-2026-10-28.md)及[办公流程](docs/AGENT-WORKFLOWS-IMPLEMENTATION-2026-10-28.md)。

## 开发与验证

源码采用 TypeScript 和 React/TSX：`src/host.ts` 为 Host 入口，`src/client.ts` 为 Client 入口，`src/shared/` 维护共享契约，`src/cli/harness-linky.ts` 为 CLI 入口。构建生成 `index.js`、`client.js`、`bin/harness-linky.mjs` 和 `bin/knowledge-embedding-worker.mjs`；不要直接编辑生成文件。模块职责见[源码导航](src/README.md)。

```sh
pnpm install --frozen-lockfile
pnpm --dir plugin-tests install --frozen-lockfile
pnpm build
pnpm check
pnpm test
pnpm test:layout
```

`pnpm check` 包含严格类型、架构、产物一致性与语法检查；`pnpm test` 运行 Host 场景及客户端交互回归；布局测试使用隔离浏览器与合成数据。可选宿主集成测试见[rc.5 集成说明](host-integration/rc5/README.md)，需要单独准备对应宿主源码或运行环境。

本地源码安装：

```sh
dsh plugin --profile desktop add .
```

真实账号、厂商网页与多日运行的验证范围应以对应记录为准；单元测试、合成消息与协议夹具不等同于真实业务投递或执行。历史桌面验证见[桌面记录](docs/DESKTOP-VALIDATION-2026-10-28.md)和[稳定性记录](docs/RELIABILITY-VALIDATION-2026-10-28.md)。
