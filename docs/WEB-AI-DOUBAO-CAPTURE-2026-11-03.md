# 豆包过程说明被误当成完整回答

## 现象与定位

原版 Harness 的豆包回答只保存两段检索说明，而同一内嵌官网对话已经显示结论、技术栈表格、代码及末尾总结。

通过工作台内置的“检查网页兼容”读取实际页面结构，确认同一个 `receive_message` 根节点下有三个 `message_text_content / md-box-root` 正文片段，前两个片段分别约 47、36 字符，第三个约 2977 字符。原选择器能够识别三个片段，无须扩大到整页读取。

旧结束逻辑允许“当前已出现的所有 Markdown 片段各自结束”作为整轮完成证据。豆包检索说明可以先结束，最终回答随后才挂载，因此旧逻辑会在最终正文出现之前结束采集。该问题位于结束判断，Markdown 渲染不会凭空补回未采集的文字。

## 修复

- 为网页适配器增加 `completionScope: 'controls'`，豆包启用此规则。
- 豆包仅使用当前回答根节点内可见、可用的 `message_action_regenerate` 作为整轮结束证据；停止按钮仍优先判定生成中。
- 片段、包装节点或其他轮次上的完成属性不再结束豆包当前轮次。
- 保留当前正文选择器、DOM 顺序、多块合并、去重、轮次归属、稳定复核和持久化流程。
- 其他厂商保持既有结束规则。无法确认结束时仍保留内容并提示核对，不把暂时停止更新视作完成。

## 验证

- `pnpm build`、`pnpm check` 通过，268 个模块无循环或层次问题。
- 专项测试 5 个文件、102 项通过，日志 `/tmp/workbench-doubao-focused.log`。
- 新增 6 个豆包回归场景：过程说明先结束后追加结论；旧轮次按钮及包装属性隔离；隐藏/禁用结束控件及停止按钮优先；表格与代码正文；停顿超过十秒后出现结论；连续追问等待完整回答后才发送下一问。
- 原版 Harness 内嵌实机：进入用户提供的既有主题，豆包页签复现只有两段说明；官网同一对话确认存在完整结论。构建修复后通过“采集本轮回答”恢复，工作台 AX 树与截图均显示结论标题、两个表格、代码、第五节总结及最后一段建议。
- 本次实机只采集已有回复，没有向官网重新发送问题，没有清理登录或启动其他浏览器/测试版。
- `pnpm test` 全量通过，包含 Host 回归及 43 个界面测试文件、677 项界面测试。日志 `/tmp/workbench-doubao-full.log`。
