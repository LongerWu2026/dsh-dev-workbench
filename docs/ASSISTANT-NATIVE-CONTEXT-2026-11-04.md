# AI 助手与 Harness 原生上下文

用户消息只向 `sessionController.prompt` 提交原文和附件。事项数据、引用、知识设置及本轮约束不再拼到用户消息里。

## 入轮与展示

- 使用原生 `agent/pre-step` 扩展点，在实际接收用户消息时加入独立的 `user/message` 上下文，来源为 `dev-workbench-context`、形式为 `snapshot`。
- 以原生 `sessionId + source.rpcId` 配对；上下文紧邻其对应用户消息，保留原始用户对象与附件。
- Harness 根据非用户来源将其渲染为默认折叠的上下文行，模型仍可读取。AI 助手不把该行重复显示为用户发言。
- 新记录依据独立上下文的请求来源显示原文；旧的拼接消息继续使用原有兼容清理，不改写历史。
- 普通会话、事项会话、原来的办公问答发送路径均使用该通道。后台结构化识别和资讯处理任务的协议维持原状。

## 会话与重试

沿用当前会话、工作区和请求编号，不额外创建会话或发一次隐藏 prompt。没有使用“先 inject、再 prompt”，避免先到的运行轮次取走排队上下文。

上下文在发送前以私有文件保存到本地 `assistant-native-contexts`，重载后仍能处理已排队的原请求。记录不保存附件字节及上传凭证。重复登记复用上下文消息 ID；已提交或已在本轮决策中的快照不重复插入。

附件明确拒收后重试继续使用原快照；不能把新原文、不同引用或另一会话复用到同一请求。请求接收状态不明确时沿用现有查收逻辑，不自动重发。缺少原生上下文能力时明确报错，不降级为污染主消息的拼接模式。

## 验证

- `tests/assistant-native-context.mjs`：请求与会话隔离、批次顺序、重载、重复提交、纯附件、停止和归属校验、原文及历史显示。
- `tests/assistant-attachments.mjs`：实际 Hub 发送内容与单次提交、附件失败重试和接收不明场景。
- `host-integration/rc5/test-native-context.mjs`：已安装 Harness 的公开 Agent 瀑布钩子、真实 Session 事件与模型可见消息；核对已安装原生界面的默认折叠契约。
- 全量 `pnpm test`、`pnpm build`、`pnpm check`。

原生 SDK 验证使用临时合成会话，不向模型发送实际请求、不修改用户会话；默认折叠的核对属于已安装渲染器契约检查，不等同于客户端点击验收。
