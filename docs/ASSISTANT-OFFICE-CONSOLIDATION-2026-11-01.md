# 智能办公合并到 AI 助手

本次将操作入口与处理结果集中到 AI 助手，保留任务中心、待回复、研发任务等真实业务清单。后台 jobs 仍负责执行、重试和恢复，不再单独构成一个面向用户的办公产品。

## 使用方式

- 从 AI 助手的常用操作进入日报、周报、批量回复草稿和忙碌自动回复设置；通用办公事项使用固定的“日常工作”会话。
- 待办处理方案归对应待办会话；单条回复归对应待回复会话。再次进入继续原记录，不因切换页面重新执行。
- 产物在聊天内展示，保留复制、保存候选知识及采纳为回复草稿等操作。采纳草稿不等于对外发送。
- 忙碌自动回复继续采用现有私聊告知规则，用户明确开启后生效。移入助手本身不改变设置，也不向任何人发送消息。
- 旧“智能办公”地址进入 AI 助手；历史报告、草稿和处理记录按归属保留，不删除业务数据。
- 首页和资讯等列表只保留当前处理状态及进入助手继续处理的入口，不重复展示后台作业编号和列表。

## 验证边界

本轮使用隔离数据验证业务操作、历史归属、重试及草稿采纳。真实客户端仅检查导航、历史显示和只读操作，不发送企业消息、不开启自动回复、不执行真实研发任务。

验证结果：

- `pnpm build`、`pnpm check` 通过，234 个源码模块的架构检查通过，构建产物与源码一致。
- `pnpm test` 完整通过，包含全部 Host 回归与 32 个 UI 测试文件、491 个 UI 用例。
- 新增办公会话后端测试 21 项，覆盖真实结果归属、重复请求、同一任务成果去重、报告内容/日期变化、采纳草稿保护、忙碌回复确认及历史上下文。
- 助手交互目标测试 49 项通过；办公会话、报告、批量选择和自动回复设置的亮暗/窄屏布局 64 项通过，无页面错误。
- 导航布局 20 项、通用布局 189 项、连续识别进度布局 16 项通过。
- 在目标加载前切换会话、关闭助手或读取失败会取消尚未提交的操作；重新进入不会自行执行旧指令。未知自动回复状态不会显示为关闭。
- 实际客户端已将当前工作区链接的插件组件停用再启用，确认恢复运行。主导航已移除“智能办公”，任务中心、待回复保留；“日常工作”能读取原有处理记录、工作报告及回复草稿，显示复制、存候选知识和采纳入口。
- 实际打开“自动回复设置”仅执行 `busyReply.status`，在聊天内生成可追溯回执，设置显示关闭并保留私聊告知规则。没有切换开关、采纳草稿或生成真实报告；验证后已关闭设置弹窗，停留在日常工作会话。
