## 后台历史归档与宿主兼容

此前仅检查 SessionController 后认定“无归档接口”是不完整的。已核对本机安装包公开声明：

- `@deepseek-ai/dsh-workspace`：`ctx.workspaceRegistry.archiveSession(id)` 和 `archivedSessionIds`。归档保留日志与工作区归属，仅隐藏分组列表。
- `@deepseek-ai/dsh-agent`：AgentRegistry 的 `get(id)` / `resume({resumeSessionId})`，以及 Agent 的 `idle/running` 状态。
- 当前接口未提供 unarchive/恢复侧栏方法。界面明确告知此边界，不直接修改宿主数据库。

设置页新增默认折叠的“管理后台会话历史”：分页查看、选择本页旧会话、归档选中、查看已归档、打开原生日志。后台再次校验登记 ID、当前复用/人工会话、运行状态和异步期间的变化。批量部分失败逐条报告；未知状态不视为闲置。

实机发现当前宿主没有 `sessionController.state`：归档改用公开 AgentRegistry 判断活动状态；后台冷启动复用增加 sessionController.resolveAgent 兼容，恢复原会话 ID，不因缺少 state 接口就另开会话。真实日志不存在才走既有恢复逻辑。

这里只处理工作台已登记的后台 ID，不会按相似标题猜测并归档用户聊天。当前后台会话保持复用，不会自动归档仍被任一账号线程使用的会话。

## 实机追加发现及修复

- 原生日志导航改用 Client 的 sessions.open(id)。打开之后不能再 selectPanel(null)，否则宿主会清除刚选中的会话；已通过原生日志页面验证。
- 真实冷恢复发现：直接调用底层 agents.resume 会绕过宿主模型选择及预设装配，报 `prompt variable "{{model}}" has no value`。改走控制器公开的 resolveAgent(id)，保留原会话身份及宿主装配。恢复异常保留原ID，不以另建会话掩盖错误。
- YAML默认示例第二个列表项会触发旧手写解析器错误。改用打包到Client内的yaml库，本地转换，不上传输入；默认列表、嵌套、块文本双向转换、重复键和别名拒绝均有行为回归。原生软件默认示例已成功。
