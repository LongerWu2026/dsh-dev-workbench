# 普通聊天按需检索知识

## 行为

- 普通聊天 `chat:*` 的自动模式不在发送前进行关键词或向量检索。会话继续使用 Harness 原有的工作区、上下文、目录/文件/运行状态工具。
- 问题需要已保存的规范、项目资料或经验时，由模型调用已有 `workbench_knowledge_retrieve`；核对片段原文使用 `workbench_knowledge_read`。检索后仍由模型根据真实资料回答，不保证模型在每次问题中都会选择查询。
- 尚未查询的轮次使用 `deferred / agent-on-demand` 标记，不冒充“未命中”，不显示知识卡片。实际查询后才显示本轮知识依据；历史真实检索记录保留。
- 仅知识库模式保持先检索、未命中不调用模型；关闭模式不预检索，工作台知识工具也不能在该轮自动查询。专用业务会话的自动预检索保持原行为。

## 范围与引用

1. 知识工具读取真实原生执行会话的项目、来源账号和知识空间，模型参数不能切换范围。
2. 只召回当前范围内已确认有效资料；读取时再检查本轮返回过的片段 ID、版本及范围，不能直接使用上一轮 ID。
3. 实际检索登记到原 session、turn、fromSeq；同轮多次查询合并引用。未检索占位不覆盖实际结果。
4. 增量读取提供最新知识依据及引用核验；未查询却引用知识时明确提示无法核验。正文与会话标题不包含注入的知识模式说明。
5. 检索等待期间会话轮次或范围变化时，旧片段不返回给新范围。

## 验证

- `pnpm build`、`pnpm check`：通过，含类型、架构及构建一致性。
- `node tests/knowledge-on-demand.mjs`：14 项真实 Hub/工具链路测试通过，使用隔离状态和模拟原生模型。包括普通问题零 Embedding 请求、按需读取、引用归属、同轮合并、跨轮拒绝、范围伪造、关闭模式、仅知识库、专用会话及等待期间范围切换。
- `pnpm test`：全量宿主测试及 49 个文件、743 项界面测试通过。原有知识检索与空间隔离回归保持通过。
- `node plugin-tests/layout/knowledge-on-demand.mjs`：12 组布局通过，覆盖 360/640/1280px、明暗主题、未查询/已查询状态与草稿保留；窄屏知识设置无溢出。
- 原版 Harness：在既有普通聊天中打开知识设置，确认“自动（按需检索）”及说明已显示，随后关闭设置；未新增模型问题、未改知识数据或登录。
