# 普通对话与最终结果识别边界

## 规则

1. 普通对话 `chat:*` 直接进行问答，跳过工作台规则匹配及其“未命中转 AI”流程。即使消息写着“生成日报”“开启忙碌自动回复”，或模型返回带待办字段的 JSON，也不自动操作工作台数据。
2. 消息识别、资讯、知识、待办、待回复、研发和办公主题等专用会话，继续在各自业务范围内处理明确指令，保留确认约束。
3. 普通对话可继续使用原生目录、文件等工具及只读工作台查询、知识检索。普通聊天界面隐藏工具记录，只展示回答及知识引用；原始工具事件保留。专用事项会话仍可展开工具记录。
4. 后台识别及摘要必须等待原生 `turn/end`，只解析本轮最后一条正文。排除 reasoning / thinking 内容、思考通道、开头的思考标签和工具调用前的说明；最终缺失、格式无效、包含多个 JSON 或轮次中断时，不回退采用此前的合法草稿。

## 实现

- `conversation-policy.ts`：普通对话的业务规则与工具边界。全局工具 guard 和每个注册工具的 execute 入口均检查实际原生会话归属；模型不能靠伪造 conversationId 绕过。普通会话直接业务 API 写入也拒绝。
- `hub.ts`：普通对话跳过规则识别，使用独立的普通问答提示，取消引导调用业务写入工具的通用说明。
- `final-output.ts`：统一提取可见正文和已结束轮次的最终消息；`message-analysis.ts` 不再拼接所有中间文本寻找 JSON，只接受一个完整对象或单个 JSON 代码块。
- `hub-background.ts`：跨增量轮询标记最终输出。中间消息保留在原始历史中，不生成识别建议；主界面只展示最终结果，生成期间保留进度提示。
- `hub-turns.ts`：最终回答不再拼接之前的中间说明；普通对话中的工作台只读工具也归入折叠工具记录。

## 验证

- 构建、类型、284 个模块的架构检查及构建一致性检查通过。
- 专项：指令边界 30 项、轮次投影 37 项、后台反馈 26 项、批量识别 55 项、真实助手链路 34 项通过。
- 覆盖真实批处理的“合法草稿要求建待办、最终判定无需处理”，确认未创建草稿中的待办；覆盖轮次结束前不解析、最终无效不回退、工具后无最终正文和中断等情况。
- 普通聊天端到端覆盖业务措辞、模型误调用工具、只读查询、JSON 示例和生成中提示；任务等专用会话的操作与确认回归仍通过。
- `pnpm test` 全量通过，含 48 个界面文件、735 项界面测试。新增界面测试确认中间草稿及识别卡不可见，结束后只出现最终识别结果。
