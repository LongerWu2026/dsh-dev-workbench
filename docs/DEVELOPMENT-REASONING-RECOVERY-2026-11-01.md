# 研发任务的推理历史兼容接续

研发任务继续执行时，若历史消息缺少当前模型要求的 `reasoning_content`，保留原生会话，新建同一工作区中的兼容会话，并接续未完成进度。普通 400、网络错误和历史日志不可读不会触发随意换会话。

## 会话与模型

- 从失败会话的原生 `model/selection` 或最近 `request/header` 读取 provider、model 和 reasoningEffort，通过 `sessionController.selectModel` 设置新会话。不会使用 CLI 适配器配置中的模型代替用户当前选择。
- 契约核对来源：项目内 `.local-host/rc5-source/packages/api/session-controller/src/{types,commands,model-selection-projection}.ts` 与[宿主公开源码](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/api/session-controller/src/commands.ts)。
- 只移交任务要求、阶段结果、测试证据、已有助手摘要和当前工作区差异，不复制旧 assistant/tool 协议消息，不伪造或提取历史推理正文。
- 分配新会话及选择模型的进度写入任务文件。已记录新 ID 后，归组或模型设置失败会复用该 ID。用户暂停时，已返回的创建结果仍会记录。
- 原会话保留在原生工作区、任务详情和会话过程里，继续纳入研发会话隔离范围；不会归档、删除、清空或改名。
- 同一阶段、验证周期及目标模型只做一次兼容替换；兼容会话仍报同类错误会暂停，重复点击继续不会无限新增会话。
- 兼容会话失败后记录宿主 SDK 序列化器指纹；实际适配器更新后，允许手动继续同一个兼容会话一次。适配器未变化时仍不重复提交。链接开发插件时也从宿主入口定位 SDK，不依赖插件私有依赖恰好包含宿主包。

## 不重复完成的步骤

- 完成的分析、开发等阶段依据持久检查点跳过。原生轮次已完成但流程尚未记账时，从保存的事件游标核对完成证据。
- 多条测试按命令和代码指纹复用通过结果，只重试失败命令；代码变化、测试命令变化或明确的新要求会重新验证。没有可核对结束证据的请求会暂停，不自动重发。
- 新要求或退回修复开启新的验证周期；代码变化使旧测试和审查失效，不能沿用旧批准。
- 失败阶段内部可能已有文件写入或工具操作。接续提示要求模型先核对真实工作区，只完成缺失部分；插件保证流程阶段和可核对测试的检查点，无法替原生模型保证任意工具操作的 exactly-once。
