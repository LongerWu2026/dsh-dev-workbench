# 官网完整回答采集与连续追问（2026-10-29）

本轮使用原版 DeepSeek Harness 的「智能工作台 → 多 AI 对话」，复用已登录的六家账号。全程没有启动本地测试版、另开浏览器窗口、重启应用或清理登录数据。问题均为临时标签、代码和上下文记忆等合成测试，不发送工作内容。

## 实现

- 按一轮助手回答合并多个正文块，按 DOM 顺序采集；保留段落、列表、链接及代码缩进。隐藏副本、思考区域、操作按钮和代码行号不会混入正文。
- 发送前保存回答数量及上一回答的身份锚点；追问沿用该厂商在当前主题的会话。只读恢复按问题和基线定位本轮，可在后续追问存在时重新采集较早回答。
- 完成状态需要本轮的结束标记及连续两次稳定正文；正文暂停、停止按钮瞬间消失、上一轮操作栏或页面级完成属性均不足以表示本轮完成。超过 60000 字符、休眠或无法确认归属时保留待核对，不重新发送。
- 批量支持最多五问，两家官网并行，同一官网严格等待上一答完成后再发送下一问。一家需要登录、核对或人工操作时阻止其后续问题，其他厂商继续；Host 端也执行同样的顺序检查。
- 原主题在页面重新加载后恢复；完成记录可「重新采集本轮」，未完成记录可「采集本轮回答」，两者都不会重新提问。取消只停止采集，不撤回官网已收到的问题。
- 状态保存和取消遇到临时网络错误时，最多重试相同的、带执行租约的状态更新两次；不重试创建请求、官网提交或有歧义的发送。

## 六家适配

| 厂商 | 正文及结束判定 |
| --- | --- |
| Kimi | 合并 segment 内多个正文块，使用本轮动作栏及编辑器就绪状态 |
| 智谱清言 | 按 answer 根节点合并 markdown-body，使用本轮导出操作；提交时短暂激活工作台内嵌区域，官网确认接收后收起 |
| 豆包 | 按 receive_message 根节点合并正文，识别本轮流式完成属性 |
| 元宝 | 忽略零高度裁剪副本，使用本轮重新生成操作；等待晚到的结束控件 |
| 千问 | 使用 qk-markdown 及完成类，剔除语法高亮行号，保留真实数字和代码缩进 |
| ChatGPT | 适配同一轮同时包含提问与回答的新结构，只取助手 Markdown；保留 Read aloud 对旧轮的定位，支持 display:contents 和 CodeMirror 代码块 |

实现分布在 `src/shared/web-ai-observation.ts`（官网观察）、`web-ai-adapters.ts`（声明式适配）和 `src/client/features/web-ai/` 的 `capture.ts`、`runner.ts`、`batch.ts`、`NativeWebsite.tsx`、`WebAIPage.tsx`。Host 端的状态与执行租约在 `src/host/application/web-ai-service.ts`。

## 验证与范围

- 六家各完成首问和追问，验证首尾标记、代码缩进、临时标签记忆和相同官网会话；修复后另跑六家两问批量，24个对应回答均已保存。
- Kimi长回答中途停止后只读恢复，最终1300字符、24个编号条目、首尾标记及代码缩进通过；基线4轮，最终官网回答序号4（从0计数），恢复采集没有增加提问轮次。
- `pnpm build`、`pnpm check`、`pnpm test`通过；140个模块无数字前缀、循环依赖或分层违规。118项React测试（官网40、采集23、批量/回写5）、Host smoke240项、网页业务35项通过；布局103场景零错误、零失败。
- 实机发现的临时网络回写失败已经保留原文并通过只读恢复；相同回写的自动有限重试由故障注入测试覆盖，最终版本实机取消和恢复通过。早期未发送/取消的合成记录保留，不改写成成功。

最终实机矩阵及工程结果见 [验收证据](evidence/web-ai-capture-followup-2026-10-29.json)。证据仅记录合成测试标记、状态、长度与布尔结果，不包含账号、官网会话地址、Cookie 或授权。

本轮覆盖当前已登录会话的发送、完整正文、结束判断、同会话批量追问及只读采集。跨重启登录、账号过期/切换、验证码和实际系统休眠仍按原待办保留；本轮未验证这些条件。官网结构或账号状态再次变化时仍可能需要人工核对，界面会保留原对话入口。
