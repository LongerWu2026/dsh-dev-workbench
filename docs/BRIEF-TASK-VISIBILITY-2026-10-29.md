# 今日简报与任务中心的展示一致性

简报和任务中心共用本地业务快照，不分别维护任务数据。页面前台可见且未打开待办编辑时，每12秒查询业务修订号，变化后才读取新快照；窗口重新获得焦点或页面恢复可见时立即检查。正在编辑待办时暂停自动快照替换，避免打断输入。云之家消息采集仍是北京时间09:00–21:00每5分钟一轮，采集、AI识别和本地快照展示是不同阶段。

## 此次原因

原“今日待办”只挑选逾期、今日到期或高优先级事项，且最多展示8条。普通优先级、没有截止日期或明天才到期的新任务，即使已入任务中心也不会出现；等待12秒或重新同步消息不能改变这个筛选结果。

## 修改

- “今日关注”纳入北京时间当天新建的未完成待办，既有逾期、今日到期和高优先级条件保留。
- 新建事项按建档时间倒序排在前面，避免被多条旧逾期事项挤出前8条。这里“今日新增”指待办建档日期，不冒充原消息日期，也不因编辑旧任务而变成新增。
- 提供“今日关注 / 全部未完成”切换及明确计数。超过8条可直接展开、收起，并显示已展示数量，避免误以为任务丢失。
- 已完成、已取消和已归档任务不参与未完成列表，归档任务不再混入该简报的任务计数。
- 页面每分钟及窗口恢复时重新计算当天范围，跨北京时间午夜不继续沿用昨天的“今日新增”。
- 复制今日简报使用相同的今日关注选择和顺序，超过8条标记剩余数量。

- `pnpm check`通过：类型、169模块架构、构建一致性、语法。
- `pnpm test`全量通过，React230项；新增5项真实界面交互测试，涵盖普通无截止的新任务、旧任务切换、已结束/归档排除、超过8条展开、新任务优先、复制一致性、北京时间首尾边界、12秒真实同步入口及午夜更新。
- `pnpm test:layout`153场景通过，新增800/360宽度简报切换与展开场景。
- 原版Harness重载后，真实“参加迭代立项会议”显示在简报首项；验证今日关注14条、全部未完成25条，展开显示25/25，收起后恢复8/25，最后恢复今日关注8/14。
- 实机核对时“提交代码”的当前持久化状态为completed，因此未加入未完成列表；没有为让它显示而重新打开任务。未主动修改任务内容或状态、未发送消息，也未为验证手动触发新消息采集。
