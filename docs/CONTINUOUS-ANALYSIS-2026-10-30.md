# 消息识别连续处理与进度验证

点击一次「运行分析」后创建一个持久化作业，固定每轮最多领取 50 条，处理后立即领取下一批，直到没有剩余识别消息。不同账号仍分开调用模型，超长内容仍受 40,000 字符请求保护并拆包；50 条是队列批量上限，不保证每批只有一次模型请求。「识别本条」保留限定 ID 和单条批量，不扩展处理范围。

今日简报、待回复和 Agent 中心显示累计成功处理、剩余数量、当前失败数量、已执行批数、暂停原因及北京时间自动重试时间。失败包含在剩余数量中；待人工确认已完成识别，不要求用户确认建档后才继续。临时失败按既有退避自动重试，失败三次或模型阻断明确暂停，不将尚有积压的作业标为完成。后台定时分析不会抢占连续作业。

重复点击复用进行中的连续作业，不清空进度或绕过冷却。识别结果与所属作业 ID 同次提交，重启时从结果恢复累计进度，只继续未完成消息；后台执行需要宿主进程运行。设置中的批量数用于定时识别，手动连续识别固定 50 条。
