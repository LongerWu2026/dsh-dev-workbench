# reasoning_content 历史兼容恢复

用户报告400 Missing required parameter messages[66].reasoning_content。本地模型健康记录也保留了同类错误。请求遭到拒绝的直接原因是模型要求的历史推理字段缺失；并非批量JSON条目校验失败。插件只通过sessionController提交新消息，历史HTTP序列化由宿主及模型路由处理；本轮没有证实字段具体在哪一层丢失，也没有修改宿主SDK、模型或凭据。

[DeepSeek官方推理模式说明](https://api-docs.deepseek.com/guides/thinking_mode/)要求携带tools的请求回传先前助手消息的推理内容。旧模型未返回或旧历史未保留的推理内容不能凭空补造。兼容恢复仅针对明确缺少reasoning_content的历史错误，不对普通400随意更换会话。

## 插件处理

- 正常继续复用原后台会话；仅检测到上述错误才保留旧日志、恢复一个干净的后台会话。
- 分析恢复时重发完整规则、当前批次、关联上下文和权威Task/Reply快照，保留原业务ID和人工修改。摘要同批下一篇也会使用恢复后的会话。
- 单次调用最多进行一次历史恢复，仍失败则进入现有模型有限退避/阻断；消息回排、释放租约，不消耗业务重试次数。
- 错误识别使用较完整的运行错误文本，避免原200字符截断漏掉reasoning_content。只记录错误和恢复事件，不读取、伪造或展示模型推理正文。
- 后台恢复具有挂载所有权和旧会话ID检查，不覆盖新实例已接管的会话；人工助手ID保持不变。此为后台分析/摘要兼容处理，人工聊天历史未修改。
