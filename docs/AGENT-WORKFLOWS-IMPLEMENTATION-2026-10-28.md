# Agent 中心办公执行：实现与验收

日期：2026-10-28。延续现有 TypeScript、React、Harness 模型配置与侧边助手；新增能力通过 Host 的持久作业运行。

## 本次实现

| 入口 | 行为与产物 | 业务写入范围 |
| --- | --- | --- |
| Agent中心 → 新建办公流程 → 批量回复草稿 | 一批选择1–20条待回复，按条保存草稿和依据，单条失败保留其他产物 | 用户采纳后保存本地回复草稿；不改变回复义务 |
| 新建办公流程 → 日报/周报 | 今日或近七日，上海时区；冻结输入范围，区分完成、进行中、阻塞和计划 | 保存报告产物，可复制 |
| 新建办公流程 → 待办处理方案；任务展开 → AI整理处理方案 | 汇总任务及关联来源，生成处理步骤、待补信息、交付建议和验收清单 | 保存方案产物，关联任务；尚未执行项目命令 |
| 办公执行列表 | 展示真实analysis/summary及三类办公作业，状态筛选、分页、步骤、错误、产物、取消和继续 | 只控制对应作业；历史runs另列 |
| 聊天调用 `workbench_office_workflow` | start/status/retry/cancel，启动立即返回，按真实ID查看或控制 | 与UI调用相同业务服务 |

## 可靠性与成本

- 同类、同输入并发提交在事务内去重。已完成的相同输入复用现有作业；输入变化后可生成新作业。
- 逐步落盘，重新启动后作业回排；成功步骤跳过，仅继续未完成步骤。作业执行ID防止旧轮结果覆盖重试轮。
- 取消停止后续步骤并拒绝迟到产物；在途模型调用可能继续产生费用，界面明确提示。
- 同一回复/待办/报告范围复用已有后台会话；使用既有模型选择、后台工具guard、历史兼容恢复和用量统计。每条回复有独立调用，批量表示统一提交及分项恢复，不宣称一批只调用一次模型。
- 预算耗尽延期到下一预算日，进程恢复不消耗业务重试；模型服务错误不继续消耗整批调用。
- 办公作业在队列挑选时优先；不会强行中断已有识别请求，也没有把全局模型资源改成无限并发。
- 产物必须是有界文本及真实依据ID；唯一匹配的消息ID可规范化为来源ID，未知和歧义引用拒绝。有效引用不能证明全文所有表述都正确，产物仍需审阅。
- 采纳前检查原消息、关联任务和原草稿；人工修改时拒绝覆盖。单独刷新updatedAt不视为业务冲突；对象键顺序不影响校验。
- 报告最多纳入100条任务和50条关联执行摘要，记录覆盖数量；上下文超过40000字符明确拒绝，不悄悄截断原消息。

## 代码位置

- `src/shared/office-workflow.ts`：流程类型和步骤契约。
- `src/host/workflows/office-jobs.ts`：输入、去重、模型产物验证、分步执行、取消重试、草稿采纳。
- `src/host/application/workflow-service.ts`：业务入口，调用统一后台排空器。
- `src/host/automation/jobs.ts`：持久化队列、优先级、执行归属和预算/恢复处理。
- `src/client/features/agents/WorkflowPanel.tsx`：流程表单、真实作业和产物列表。

作业、输入快照及产物进入原有jobs集合，随现有迁移包导出；不另建外部存储。现有历史执行记录及关联ID保留。

## 验证

工程检查、真实模型结果及构建哈希见 [脱敏证据](evidence/agent-workflows-2026-10-28.json)。新增隔离集成测试覆盖并发去重、单条失败、仅重试失败步骤、已有会话复用、取消迟到回包、预算延期、恢复、迁移、依据ID和人工保护；React测试通过真实点击选择批次、日报/周报/待办模板及控制操作。布局检查覆盖十页与新增办公弹窗，包含360像素宽及320像素高。

真实Harness测试选择已有两条合成验收消息，生成两条草稿，采纳其中一条；日报基于已有工作台数据，待办方案基于已有任务。没有发送企业消息、创建外部日程、执行研发命令或自动标记工作完成。
