# 多 AI 登录检查修复与验证记录

## 已修复的共用链路

- 菜单检查直接保存每个 controller 返回的状态，不再仅依赖网页回调。
- 每家检查包含页面就绪等待在内，最多 12 秒；失败或超时显示未确认，不当作退出登录。
- 同一文档的并发检查复用同一探测，避免相互覆盖回调。
- 导航、卸载和旧检查的迟到结果不能覆盖当前状态。
- 兼容性检查可以返回过滤后的账号控件结构，不读取输入值、凭据或昵称。

## 本地验证

- `pnpm check` 通过。
- 六个登录/网页专项测试文件合计 123 项通过，包含真实菜单组件的四家结果回填与单站超时隔离。
- `pnpm test` 首次因沙箱禁止监听 127.0.0.1 中断；最终正常本地权限重跑退出码 0，后端场景全部通过，前端 40 个文件共 646 项通过。

## 厂商规则依据

- 智谱：用户复制的实站诊断与 AX 均确认折叠 `aside.aside-container` 中的 `userInfoBar.sidebar-mode / sidebar-user-entry / sidebar-avatar img`。
- 元宝：用户实站诊断确认 `yb-nav__user` 中 `yb-common-nav__ft__avatar / image-container img`，配合新建对话导航。
- 千问：用户实站诊断确认 `tongyiDI-view-container` 中全宽账户按钮，有 `aria-haspopup=menu` 和头像。账户名称支持按钮文字、无障碍标签和头像 alt；排除无名称、登录入口、普通模型菜单。父按钮必须可见，头像即使尚未显示也可以作为结构依据。
- 豆包：实际页面是新版“豆包工作”，不是旧版 textarea 聊天。AX 确认打开账户菜单可见退出登录；用户第二次完整诊断确认账户 popup 按钮与 `[data-testid=sidebar_footer_setting_entry]` 为直接兄弟。最终规则使用唯一的同级账户按钮、账户名/头像及专属设置节点，不再使用未经 DOM 核实的快捷键属性推断。
- 登录探测复用一轮可见性/样式缓存，排除各厂商适配器已知消息容器，消息中的登录表单不能冒充系统账号控件。
