已修复 Kimi、智谱清言、千问和 ChatGPT 的发送入口，并在原版 DeepSeek Harness 的内嵌官网完成单次提交实测。当前入口名为「多 AI 对话」。本轮未启动本地测试版、未重启原版、未清理登录数据。

## 问题与修改

| 厂商 | 实机差异 | 修改及证据 |
| --- | --- | --- |
| Kimi | 新发送控件是 `.chat-editor .send-button-container`；用户消息根容器还包含编辑等操作文字 | 适配新控件，提问只读取 `.user-content__text`；自动发送合成问题成功，采集到“验证通过。”，不再误报为其他提问 |
| 智谱清言 | 实际发送对象是 `.enter-icon-container` 内的 `.enter_icon` 图片；裸 click 与正常鼠标按下/释放行为不一致 | 父子候选归并到最内层控件，发送前固定本轮标记，提供完整指针/鼠标事件序列；若按下阶段已清空输入则不再补 click。最终自动提交后已在工作台采集到 `OK` |
| 千问 | 文本写入 DOM 后按钮仍然真正 disabled；新版答案使用 `.qk-markdown` | 先交给官网粘贴事件处理，保留 execCommand 兼容路径，按钮启用前有限等待；实机已提交问题，官网出现新的问答及 `.qk-markdown-complete`；补充新版正文和完成标记识别 |
| ChatGPT | 新编辑器没有旧 ID，使用 `.ProseMirror`；按钮标签是 `Send`，初始化时还存在 `pending-home-input` | 优先识别真实编辑器，排除初始化占位框，适配新版 Send；沿用官网原有公开草稿“周树人是谁”自动提交，官网进入新会话并显示 Stop/生成状态 |

另外修复 `disabled:text-disabled` 这类 CSS 样式变体被误判为当前禁用状态的问题。真正的 disabled、aria-disabled 和明确禁用 class 仍阻止发送。

从用户点击发起的 prepare/submit 使用 Electron 的 userGesture 参数；observe/inspect 不声明用户操作。宿主的来源、租约和导航限制保留。不尝试解除真正禁用的按钮，不使用找不到按钮时直接回车的降级方式。

首次打开官网完成登录后，未归属主题的相同草稿可直接归入本次问题，不重新导航；不同草稿和其他已归属主题仍受保护。相同草稿仅通过布尔比对确认，不把任意官网草稿内容导出到诊断。
