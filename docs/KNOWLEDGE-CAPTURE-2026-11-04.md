# 多来源笔记与资讯原文验收

日期：2026-11-04。实现于原版 Harness 的智能工作台插件，无额外 Electron 测试版或浏览器窗口。

## 使用方式

- 云之家：打开会话 → 选择消息 → 选中单条或多条 → 复制所选消息 / 保存笔记。已读取消息在 Host 查看窗口内核验，最多合并 100 条，按发送时间排序。保存不发送 IM，不修改待办或待回复；查看消息仍沿用原有工作台已读记录，云之家客户端回执不变。
- AI 助手：每轮定稿回复底部提供复制与保存笔记，笔记默认包含问题和最终回答。流式中间输出、思考过程、工具输出不作为定稿保存。原生 Harness 的“存为知识”精确按会话及消息身份交接到工作台内同一保存面板。
- 资讯：点击标题在工作台内阅读原文，切换摘要、复制原文、重新读取或收藏原文。宿主网页提取和公开网页直接读取互为后备；GitHub 优先直读 README。无法取得完整内容时，仅收藏链接，不把摘要或截断响应当作全文。重读失败仍保留已有快照。

## 数据与检索

- 保存面板可编辑标题、内容、标签、知识空间与项目。AI 绑定项目或空间的回答不能借保存绕到其他范围。来源账号保留为来源元数据，不据此自动提升跨空间共享。
- 默认仅保存笔记；显式勾选“用于 AI 回答”后采用现有确认态和知识索引。候选、失效、归档、其他项目或其他空间资料仍受原有检索门禁约束。
- 去重以知识空间、项目、来源稳定标识及正文 SHA-256 为准，同标题不同来源不误合并，并发保存不重复写入。同一份候选再次明确用于回答时可转为可检索状态。
- 20,000 字以内正文沿用业务状态存储，长正文保留预览与快照引用，完整 Markdown 位于 `$DSH_HOME/storages/dev-workbench/knowledge-content/<sha256>.md`，单篇上限 100 万字符，超过时明确拒绝，不静默截断。
- 原始采集快照与用户编辑后的正文分开保留。知识卡片支持全文阅读、复制、编辑及回看采集原文；列表全文搜索、关键词检索与已启用的本地 Embedding 均读取完整正文。
- 迁移包内嵌被引用的正文及原始快照，包含校验信息，不携带绝对路径；预检不写文件，正式导入可从包中恢复正文文件。
- 网页直读不使用登录凭证，逐次核验公开目标、跳转和响应大小；读取的 HTML 转为 Markdown，展示通过现有 React Markdown 白名单渲染，网页脚本不进入界面执行。

## 原版 Harness 实机

1. 复制既有 AI 回答后按钮显示“已复制”；保存“验收·AI回复保存（技能数量）”，回读笔记包含问题、回答和来源快照，未勾选用于回答。
2. 云之家已读取会话选择两条消息，复制所选并合并保存“验收·云之家消息笔记（2条）”，未发送消息、未修改待办或待回复。
3. 既有 GitHub 资讯在宿主提取失败后成功通过公开网页直读取得原文；README 提取不含 GitHub 导航。收藏“验收·资讯原文收藏（LLM Agent Frameworks）”并勾选用于回答。
4. 原版知识检索测试命中新收藏的原文两段，策略为 `local-hybrid-bm25-bge-rrf`；回读第 88–95 行，显示真实知识版本及 GitHub 来源链接。复用本机已有语义模型，没有新建模型会话提问。
5. 原版组件重新加载后，本地资讯快照及已保存笔记仍可读取。原生回复“存为知识”成功打开同一保存面板并显示正确最终回答，本次取消该重复验收草稿。

三条验收笔记保留在个人知识空间，供用户复查。未删除用户数据、发布插件、重启 Harness 或修改外部业务系统。源码构建期间客户端会热刷新；Host 服务通过原版插件管理停用/启用本工作台组件加载，未替换原安装包。
