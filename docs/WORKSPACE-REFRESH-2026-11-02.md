# 首页与局部刷新（2026-11-02）

## 交互

- 今日简报右上角与全局工具栏使用相同的「刷新全部内容」：同步云之家消息及日历、识别队列中符合规则的消息、更新 AI 资讯和资讯摘要。
- 首页不再常驻「提取完成 / 识别会话 / 提取消息」操作栏。
- 首页待办、待回复卡片与对应目录增加局部刷新。只同步消息与日历并启动增量识别，不重复搜索资讯。待办与待回复使用同一分类入口，避免一次消息被分开重复判定。
- 刷新入口旁集中显示处理中、已更新或部分未完成；点击查看分步状态、累计识别数量、剩余数量、失败原因和重试时间。自动识别运行中也可从此查看进度。
- 状态弹窗中的识别恰好完成时保留最终统计，关闭后不恢复旧的首页完成操作栏。

## 边界与实现

- Host 的 `workspace-refresh.ts` 协调消息和资讯两个独立分支；一个分支失败仍保留另一个分支的结果。
- 同时点击共享采集任务；采集中局部刷新可升级为全局，不重复采集消息。识别和摘要继续复用持久后台作业。
- 显式刷新不依赖定时自动化开关；AI 识别仍尊重 AI 开关，未启用时明确提示，不偷偷更改设置。
- 普通刷新只处理新增、待识别和符合重试策略的条目。不会重判全部已完成消息，不重置耗尽重试次数，不清空模型冷却或推理历史兼容保护，不覆盖人工业务状态。
- 不通过刷新标记云之家已读或发送回复；本地快照按修订号同步。编辑任务表单时暂缓替换快照，保留草稿、附件和会话。
- 采集完成不等于 AI 完成；后台作业实际终态才决定整体结果，部分失败、等待重试、AI 未开启均不显示全成功。
- 本轮刷新协调状态在宿主内存中；Host 重载后不宣称之前采集已完成，识别及摘要的持久作业仍按原恢复机制继续。前端跨目录观察状态，断线重试，不因读取状态失败伪造业务失败。
