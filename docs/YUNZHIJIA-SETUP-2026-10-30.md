# 云之家安装及免重启检测（2026-10-30）

## 行为

- 设置页新增安装、登录授权、主动重新检测；操作立即返回，离开页面后由 Host 继续持有，可点击重新检测读取结果。
- 未安装时显示「安装」，已安装（包括待授权、已连接）时显示「重新安装」；操作进行中禁用按钮，避免重复启动。
- 使用与其他连接器一致的 `wb-item`、标题和副说明样式，名称、状态与小号操作按钮同行，窄屏允许自然换行。只保留一句「同步云之家消息与文档，安装时获取最新版 CLI。」，不显示安装要求、自动检测说明或原始接口错误。进入页面、定时停留及窗口返回均不检测连接；只在点击重新检测或安装/登录结束后验证。操作进行中每3秒仅查询进度和本地快照，不调用连接探测，结束或页面卸载后停止。
- 安装与登录单实例运行，有超时、输出上限及停用清理；后台只读命令白名单没有加入安装或登录。
- 安装与重新安装均显式指定官方 `@yunzhijia/cli@latest` 和 `--prefer-online`，使用 npm `--ignore-scripts` 安装至工作台目录，再将该包的二进制安装器与版本元数据复制到全新临时目录运行，确保现有二进制不会令安装器跳过下载。新文件通过 `--version` 验证后才替换托管二进制，失败保留原文件；下载目录随后清理。临时目录没有 `skills/`，安装器不会进入覆盖全局 Agent 技能的分支。
- 直接调用安装后的原生二进制，避免 npm 包的 Node shebang 依赖旧 PATH。外部安装补查 nvm、Homebrew 等常见路径，路径经 subprocess 提供方验证；重检清理旧路径缓存。
- CLI 文件存在与账号有效分开判断；只有 `whoami` 成功返回身份才显示已连接。安装、登录输出不返回前端，避免暴露授权链接；明确操作失败通过短暂提示反馈，不在连接器区域持续显示原始错误。

## 实际宿主边界

本轮没有重启正在运行的 dsh、没有发布插件、没有操作真实账号登录，也没有拉取或发送企业消息。真实安装测试调用本机子进程适配器，账号检查使用未授权夹具；不能据此宣称真实 dsh 的 subprocess 权限、浏览器授权回调或企业账号闭环已验收。新 Host 代码需由宿主重新加载一次；加载后安装 CLI 和登录不再要求重启 dsh。
