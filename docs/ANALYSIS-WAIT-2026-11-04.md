# 消息识别等待状态误报修复

## 本机只读诊断

截图对应指定单条提取作业。诊断时原消息存在，队列为 pending、尝试次数为 0，所在会话有 373 条本地消息，但仍保存会话历史补采锚点及待补采分组。作业实际为 queued/deferred，尚未执行本条模型识别；前端把所有 deferred 都按错误通知，产生“提取失败”误报。后续只读状态还观察到该作业在其他识别批次运行时返回 busy。

## 修改

- 识别结果明确区分会话补采、重试时间等待、原消息被占用；轻量状态接口保留 waitReason。
- 上述状态及其他识别批次占用统一显示为等待继续提取，不弹成功或失败提示；保留原作业并继续状态轮询。旧版本已保存的通用补采说明也兼容识别。
- 真实模型认证/执行故障、明确失败和已消耗的失败次数仍遵循原错误通知与重试策略。
- 指定消息使用队列 ID 或 sourceId 时采用同一等待判断，避免 sourceId 指定的作业被误报为 0 条完成。
- 被其他识别占用的单条作业保持等待；真实重试耗尽则停止空转并明确提示人工重试。自动退避沿用队列原重试时间。
- 保留补采游标、既有结果、次数和原生会话。没有为验收重新提取该真实消息或调用模型，也没有手动修改业务状态；实际单条消息是否完成以补采后原作业结果为准。
