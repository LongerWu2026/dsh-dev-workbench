# 研发任务统一列表与右侧过程（2026-11-04）

原页面上方搜索 Linky 工作项，下方搜索本地研发会话，两处入口对应两份列表。现在只保留一处工作项搜索，将同一工作项的本地研发进度合并到左侧条目，选中后在右侧直接展示，不再通过下方折叠区或“打开研发过程”跳转。

## 当前行为

- 左侧：统一工作项列表；按工作空间、类型、业务状态和是否显示已完成筛选。搜索同时匹配编号、标题与已有研发会话编号。
- 右侧：已有研发记录直接呈现原任务的阶段、暂停原因、真实差异、测试输出、审查入口与会话过程；尚未开始的工作项显示完整描述和“选择工程”入口。
- 合并同一条目时按任务/工作项身份匹配，业务状态与研发阶段分别显示。远程当前页未覆盖的本地记录仍可在当前范围中查阅，并标记来源；离线时可以查看本地历史。
- 从 AI 助手定位任务、重新进入页面、切换工作空间或刷新时保留原任务身份；不同选中项的迟到响应不能覆盖当前内容。详情归属不符时保留原内容并报错。
- 查阅不发起准备或开始执行命令，也不另建讨论会话；沿用宿主对既有工作区和会话的关联检查。开始、继续、审查和回写仍需对应明确操作，沿用原记录与完成进度。
- 桌面采用左右布局并分别滚动；小于内容区断点时改为上下布局，避免把研发过程挤窄。保留一处刷新任务入口。

## 验证

- `pnpm build`、`pnpm check`：构建、类型、架构与产物一致性通过。
- `pnpm --dir plugin-tests test --maxWorkers=1 --minWorkers=1 tests/development.test.jsx`：43 项通过，含直接展示、合并去重、单一搜索、跨空间定位、离线读取、恢复选择、完成记录查阅和迟到回包隔离。
- `node plugin-tests/layout/development.mjs`：45 组明暗/尺寸/页面状态检查通过，涵盖 360、800、1280 宽度，核对左右/上下布局、标题行数、列表边界及弹窗；截图与报告在 `.tmp/development-redesign/layout/`。
- `pnpm test --maxWorkers=4 --minWorkers=1`：全量 Host 脚本与 50 个界面测试文件的 777 项测试通过；最后合并刷新入口后另行通过 43 项研发回归及 45 组布局检查。

这些验证使用合成工作项与隔离测试环境，没有修改用户真实 Linky 工作项、研发阶段或会话内容。

## 研发会话统一在 AI 助手打开

“打开 Harness 开发会话”改为“在 AI 助手中查看会话”。开发主会话、审查会话、逐段会话与兼容前原历史入口都传递当前研发任务 ID 和精确的原会话 ID，通过一次页面状态更新打开对应 AI 助手页。原有不指定会话的助手入口保持默认行为；审查/历史会话沿用 Host 的归属及只读限制。不调用宿主原生聊天跳转、不提交新问题、不新建会话或重跑任务。

验证：50 项研发/宿主客户端界面测试、1 项完整助手路由测试、22 项原生绑定验收和 45 组研发布局检查通过；构建检查通过。构建中发现现有消息识别筛选集合缺少 `string` 泛型，仅补充类型声明，连续识别 35 项回归通过，未改变业务逻辑。

## 研发页只在内部滚动

研发页外层按宿主实际可用高度固定，不再用屏幕高度估算内容区高度。左侧列表与右侧详情各自滚动，切换工作项只重置右侧位置，外层页面保持不动；小窗口仍采用上下分区，过矮时筛选栏、提示区和原生执行记录也可在各自区域内部滚动，避免直接裁掉内容。页面范围样式只在研发页启用，其他页签恢复原有滚动行为。

验证：88 组研发尺寸/明暗/状态检查通过，包含 360×360、800×480、1280×480 以及详情滚到底、外层仍保持零滚动范围的检查；全量 783 项界面测试和 226 组整体布局检查通过，最终构建检查通过。截图文件名包含窗口宽高，位于 `.tmp/development-redesign/layout/`。
