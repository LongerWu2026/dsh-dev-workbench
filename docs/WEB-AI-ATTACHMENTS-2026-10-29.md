# 多 AI 对话附件方案与实现

结论：可在原版 Harness 的现有内嵌官网中实现，无需另起 Electron 或浏览器窗口，也无需接入模型 API。

## 使用方式

统一输入区支持普通文本粘贴、截图/图片文件粘贴、文件选择和拖入。图片显示缩略图，附件可逐项移除；未填写问题时明确使用“请分析所附附件，并说明关键内容。”。支持选择 PNG/JPEG/WebP/GIF、TXT/Markdown/CSV/JSON/LOG，以及 PDF 和常见 Office 文件；官网仍可能限制具体格式、模型和额度。千问当前网页会以文档覆盖图片，因此同一问中混合图片与文档会在传输前拒绝，需分开提问。

最多五个附件，单个不超过 10 MB，总计不超过 20 MB；同次选择不接受重复文件名，避免回执歧义。连续粘贴的同名图片会自动编号，例如 `image (2).png`。只向勾选的厂商传输。批量仅在首问上传附件，后续问题使用官网会话上下文；所有厂商首问完成后清空本地附件选择，避免追问重复上传。“上传附件并填入”会上传文件并填入问题，保留手动发送。

## 技术路径

1. 浏览器文件选择或 Clipboard/Drop 提供 `File`；只读取用户明确提供的文件，不根据聊天中的路径读取磁盘。
2. 校验格式、数量和大小，使用 FileReader 在渲染端临时编码；图片预览的 Object URL 在移除和卸载时释放。
3. 每个内嵌官网在已登录的 Session 内接收文件。优先使用已存在的文件输入；也支持官网粘贴/拖入处理，以及附件菜单临时创建的文件输入。菜单路径暂时拦截该官网文件输入的 picker 调用，将已选文件交回其回调后立即恢复，不再弹出第二次系统选择框。
4. 校验官网显示的文件名或新增图片预览、上传/解析状态及发送按钮，连续两次就绪后再核对所有附件仍然存在，才允许发送。菜单、类型或回执不明确时停止该厂商，不降级成无附件提问，不自动重传。
5. 附件上传需要激活内嵌页面，因此有附件的批次逐站执行；纯文本保留最多两站并行。同站问题保持顺序。
6. 创建问答发生临时传输失败时，只对原请求标识有限重试，宿主已有去重；失败后仅取消本请求的剩余队列，不重传文件或重发官网消息。
7. 上传期间可能恢复旧会话，发送前重新读取采集基线；官网新建会话导致计数归零时，结合会话指纹及精确问题绑定新回答。
8. 官网对重复文件名追加 `(2)` 等数字时，按原始基名、数字序号和扩展名确认回执；不接受相似的其他文件名。千问仅在已知附件列表中把 `avatar` 标记识别为上传缩略图，普通头像仍排除。
9. 用附件预览签名保护未归属草稿。已确认上传的签名在内嵌控制器内暂存，允许同主题追问；换主题或释放租约即清空，不把另一主题文件自动带入。固定输入区边界不因空输入隐藏发送按钮而扩展到页脚图标。

基础能力来自 [Electron webview](https://www.electronjs.org/docs/latest/api/webview-tag) 和标准 [DataTransfer/FileList](https://developer.mozilla.org/en-US/docs/Web/API/DataTransfer/files)。固定适配只在六家允许的 HTTPS 来源运行，不使用厂商私有上传接口，不读取或复制登录凭据。

## 持久化与恢复

附件字段只保存 ID、名称、类型和字节数，兼容旧记录；文件字节、Base64、本机路径及预览 URL 不进入 Host 存储或业务导出。模型回答仍按原有逻辑保存，可能包含模型引用的文件内容。刷新后需重新选择文件。取消或超时不会撤回已经交给官网的文件；保留原对话供核对，只读恢复回答不会再次传输附件。

实现模块：`src/shared/web-ai-attachments.ts`（契约）、`web-ai-upload.ts`（官网上传）、`src/client/features/web-ai/attachments.tsx`（选择与预览）。调度、采集及 Host 校验沿用原有模块。

早期记录不包含附件元数据，不能代替新版端到端验收。仅在原版插件管理中停用/启用“智能工作台”组件使 Host 加载新版协议，未重启原版、未清理Cookie。当前协议记录已证实业务文件仅包含附件四项元数据。普通文字粘贴、Clipboard文件、同名图片、限额、无附件回执保护由工程测试覆盖；原版文件选择、图片预览和移除已再次实测。尝试系统截图快捷键后，实际剪贴板仍为合成路径文本，故未按原生图片粘贴成功计；该路径仅进入输入框，未被当作文件读取或发送，已清空。

最终结果见[脱敏证据](evidence/web-ai-attachments-2026-10-29.json)。待办70按基础能力核销；逐站、格式和账号补验保留71。PDF/Office由官网解析，本项目不新增本地文档转换服务；本轮 PDF/DOCX 使用合成代号 PDF-742、DOCX-742 及数量4、5。其余 Office 格式、账号过期、跨重启恢复仍不按通过处理。

工程验证：`pnpm build`、`pnpm check`、`pnpm test`、`pnpm test:layout`及`git diff --check`全部通过。全量测试包括152项React测试（附件24项）、网页业务Host40项；113个布局场景包含明暗主题、800/360宽度、长附件名和移除操作。未启动持久化测试包或额外可见浏览器。

解锁补验同时修复：官网重复文件名追加数字序号的回执、千问附件列表中名为 avatar 的真实缩略图、完整输入区边界、千问混合附件预检，以及可见安全验证弹窗的停止提示。所有验证复用原版已登录账号，未处理验证码或启动测试版。
