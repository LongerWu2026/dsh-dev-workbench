# 数据查询工作区实施计划

依据：已批准的 [设计](../specs/2026-11-07-data-query-workspace-design.md)。

## 测试边界（沿用已批准设计）

- 公开数据服务：保存、读取、清除工作区与 AI 完成后的持久记录；用临时资料目录和新进程验收重启恢复，不调用真实用户数据库。
- 公开查询入口：MySQL 协议夹具和真实临时 PostgreSQL（环境可用时）检验按页返回、原始 SQL 语义、截断与只读边界。
- 用户界面：通过真实组件/构建包的可访问控件验证连接切换、页面重挂载、分页、保存反馈及历史快照；浏览器测量固定视口与内层滚动。

## 顺序与并行分工

1. 保存当前未提交工作基线；现有源文件先读后改，不覆盖其他改动。
2. 并行纵向实现（每项先运行一个能复现缺陷的测试，再作最小修复，继续下一项）：
   - 独立宿主工作区存储及共享契约，包含规范化目标、白名单、容量、修订、原子提交和新进程恢复测试。
   - SQL 真分页及协议/方言回归，保留原查询排序和 LIMIT/OFFSET；截断与后续页分离。
   - 数据查询 UI 的工作区状态适配、连接/查询代次保护、固定结果视口及真实分页控件；前端和布局回归。
3. 主代理负责服务与 RPC 组合、AI 完成轮次持久提交及兼容能力检测，核对各分工接口。
4. 队友完成后主代理审查全部本次差异、运行类型/架构、构建、数据/工作区/前端/布局测试，必要时补集成回归。
5. 检查当前 GUI 的插件来源与是否具备热更新，刷新既有地址验收可见内容；宿主接口尚未加载时明确标识需要重启，不自动中断当前会话。
6. 记录完成项、真实数据库与合成测试边界、尚需用户操作的重启步骤。不声称未运行的测试通过。

## 约定接口

工作区 RPC 使用 `dataWorkspaceLoad` / `dataWorkspaceSave` / `dataWorkspaceClear`。由宿主根据连接 ID 查真实配置并计算目标身份。返回 `{id,key,revision,workspace,updatedAt}`；保存请求为 `{id,key,revision,patch}`，清除请求为 `{id,key,revision}`。`workspace` 沿用数据界面字段，持久保存内容由共享白名单约束。

SQL 请求增加 `pageSize`（50/100/200）、`offset`（原查询结果中的非负安全整数）；SQL 返回独立的 `pageSize`、`offset`、`hasMore`、`nextOffset`、截断原因及 `queriedAt`。旧调用未传分页参数时保持原先最多 200 行行为，前端新调用默认 50。

所有本次功能修改只落在职责范围内；生成的根目录构建产物由主代理统一构建，队友不运行整体构建、不修改生成产物，也不提交其他工作。
