# 数据查询固定视口、真实分页与连接级持久记忆

日期：2026-11-07
状态：交互方案已获用户确认；本文待用户最终审阅，尚未进入实施。

## 1. 目标与已确认决策

用户要求查询区域保持固定高度、宽度超出时内部滚动、支持分页，并且离开页面再返回时会话不能丢失。用户进一步确认：

1. 刷新页面和重启应用后，同样的连接信息仍恢复原记录。
2. 分页需要读取第 201 行之后的数据，不是只对已返回的 200 行切片。
3. 同意采用宿主本地持久化，保存最近一页业务数据；恢复后标记为历史结果，不自动执行 SQL。

成功标准：结果不撑破布局；SQL 真分页；不同连接不串记录；相同连接跨页面、刷新与进程重启恢复最近已保存状态。

## 2. 现状与修改边界

- 工具页用组件状态保存输入；退出整个工具页会销毁状态。选择数据库连接还会主动清空对话、SQL 和结果。
- 连接配置已保存到宿主资料目录，但没有对应的数据查询工作区存储。
- MySQL 与 PostgreSQL 查询目前最多返回 200 行；既有 `truncated` 同时表示行数、字节或单元格截断，不能据此判断是否存在下一页。
- ES / Redis 返回独立语义的 JSON。本次不把它们伪装成 SQL 表格分页。
- 工作树存在大量先前未提交修改。本次实施须基于当前内容做定点修改，不回滚、覆盖或夹带提交其他工作。

## 3. 方案比较

### 采用：独立宿主存储 + 无长期游标的 SQL 按需分页

工作区保存在当前 DSH 资料目录，通过现有数据服务 RPC 读写。翻页是新的、受限的只读查询；不持有跨页面或跨重启数据库事务。

优点：符合重启恢复要求，不依赖浏览器缓存；业务快照不进入通用工作台状态、搜索或现有便携导出；生命周期与已有数据连接一致。

代价：需要新增工作区契约、存储校验与保存冲突处理；OFFSET 型深分页有性能成本，独立查询之间没有一致性快照。

### 不采用：浏览器 localStorage 保存工作区

实现较轻，但受浏览器资料、访问入口和清理缓存影响；也不适合直接保存含密码草稿的整份页面状态。

### 不采用：长期保留服务端游标/事务

能提供更稳定的读取快照，但需引入过期、资源释放、重连和事务生命周期；应用重启后游标也无法直接恢复。超出本次范围。

## 4. 结果视口与交互

- SQL 表格数据视口固定高度 360px，包括无结果时的占位；结果工具栏和分页栏放在视口外，不随行数增长。
- 视口宽度等于中间查询栏的可用宽度。保留祖先 grid/flex 的 `min-width: 0`，不要用固定像素宽度撑开整页。
- 表格列保持可读宽度，内容不因窄栏而逐字折行。表格超宽时在数据视口内横向滚动，超高时纵向滚动；表头吸顶。
- 长单元格可使用省略展示和原文查看提示；不能静默改写复制内容。原有二进制/单元格安全截断仍明确显示。
- 提供有可访问名称且可键盘聚焦的滚动区域；空结果、加载、失败均保留合理占位，不产生页面布局跳动。
- ES / Redis 的 JSON 结果也使用有界滚动视口，保留原本结构与读取命令。

## 5. SQL 真分页契约

### 5.1 请求与返回

- MySQL / PostgreSQL 默认每页 50 行，允许选择 50、100、200 行。
- 新分页请求携带有效的原查询、当前结果偏移和每页行数；偏移必须是非负安全整数，行数必须在允许集合内，由宿主校验。
- 返回当前页行数据、列元数据、读取耗时、实际起始偏移、后续偏移及 `hasMore`。
- 行数探测、字节截断和单元格截断必须是不同事实。不得由通用 `truncated` 推断下一页存在。
- 不自动执行完整 `COUNT(*)`，不显示虚构的总行数/总页数。展示“第 N 页”“当前第 X–Y 行”“上一页/下一页”。
- 上一页依据已经访问的偏移记录恢复。若达到字节上限导致本页不足目标行数，后续偏移以实际交付的原始记录数前进，不能跳过未显示行；新请求不得重复送出整页旧记录。
- 查询结果每页仍受最多 200 行、约 1MiB 序列化行数据和现有单元格上限约束。此限制不宣称是数据库扫描量或驱动接收内存的硬上限。

### 5.2 语义与安全

- 分页对象是用户原查询的结果，不是绕过原 SQL 的筛选、排序或 LIMIT 直接查底表。
- 保留原 SQL 的 ORDER BY、LIMIT、OFFSET、聚合和集合运算语义。例如原 SQL LIMIT 200 时不能通过翻页看到其第 201 行；原查询未设 LIMIT 时可继续读取后续数据。
- 使用方言解析与结构化分页处理，不用正则替换或盲目追加 LIMIT。对无法安全处理的查询明确报错，不静默执行改变语义的查询。
- 实施计划必须选定并用测试锁定各方言处理方式，覆盖 CTE、UNION、DISTINCT、已有 LIMIT/OFFSET、尾分号和零行列元数据；不能仅证明字符串中出现 OFFSET。
- 保留单条只读语法校验、只读事务、结构指纹验证、超时、每连接串行、全局并发限制、断开/取消及失败不自动重试策略。
- 有稳定唯一排序时才能期望重复翻页顺序稳定；缺少稳定排序时提示用户。即使有排序，跨页独立查询期间数据库数据变化也可能导致结果移动；不承诺一致性快照。
- 深 OFFSET 页可能较慢，仍受现有超时限制；不自动预取全部数据。
- 修改 SQL、应用 AI 草稿、变更每页行数或连接目标时开始新的分页序列，防止旧页覆盖新查询。
- SQL 复制保留原查询；结果复制明确标注“复制当前页结果”，不暗示已复制完整数据库结果集。

## 6. 按连接识别与保存

### 6.1 身份

宿主根据已保存的有效连接配置计算规范化身份，不信任客户端自报存储键：

- 数据库类型；SQL/Redis 使用主机和有效端口，ES 使用规范化 URL（保留路径）。
- 数据库名称；Redis 空 DB 规范化为 0。
- 账号；TLS 设置及 CA 指纹作为安全上下文的一部分。

不包含显示名称、保存卡片随机 ID、明文密码或密码密文。相同目标和账号的重复连接卡共享工作区；同一连接卡改指向其他库或账号，切换为对应独立工作区。密码轮换或重命名不清空记录。TLS/CA 安全上下文变化使用隔离工作区。不做 DNS 查询或擅自合并 localhost、127.0.0.1 与主机别名。

记忆范围是当前宿主资料目录，与现有数据库配置一致；不跨 DSH 资料目录同步。

### 6.2 保存内容与容量

只保存明确白名单：

- 最近 20 轮 AI 对话及可恢复的生成草稿，与当前对话轮数上限一致。
- 未发送需求、只读/脚本预览模式、SQL 编辑内容和生成信息。
- 已选择对象引用、Redis 匹配模式、连接/AI 面板展开状态。
- 分页大小、已访问偏移、当前页，以及最近一页结果快照和查询时间。
- 最后使用的连接与目标身份映射，用于重新进入页面时恢复。

不保存密码输入表单、密码密文、运行中的数据库客户端/游标、活动请求对象或临时错误栈。对象目录/完整结构是可刷新缓存，不作为持久正确性的依据；恢复选择引用后与重新读取的目录校对。

最近一页 SQL 结果上限约 1MiB；ES/Redis 若保存原始结果快照也须满足对应 1MiB 上限。每个目标工作区总上限 4MiB，最多保留 30 个目标工作区。达到容量上限时明确提示保存失败并允许用户清除旧工作区，不静默丢弃其他连接记录。提供“清除当前连接记忆”，确认后清除该目标工作区；相同目标的重复连接卡受同一清除影响。

### 6.3 安全与存储方式

- 新建独立的固定路径、版本化数据工作区存储，由宿主管理。按白名单、字段长度、结果大小和数量验证；不接受外部文件路径。
- 目录/文件使用当前项目的私有权限与原子写入模式，序列化提交，避免并行自动保存造成文件损坏。
- SQL、对话与业务行可能含敏感信息；这些数据保存在本机，文件权限不等于加密。用户已确认本机保存最近一页快照。密码继续使用现有内存/钥匙串机制，不能进入工作区文件。
- 工作区数据不并入通用快照、通用搜索或便携迁移包。本次不新增云同步、跨机器同步或加密体系。
- 文件损坏或写入失败必须反馈；不以“空工作区”静默覆盖损坏文件。恢复读取失败时允许使用页面并重试，但不得宣称已经保存。

## 7. 生命周期、竞态与失败处理

- 页面进入时加载最后使用的有效连接工作区；选择连接时保存当前修改并加载目标记录。没有记录才展示默认查询。
- 从存储恢复不执行 SQL。最近一页明确标记“上次查询结果”并显示时间；用户点击执行或翻页时才读取数据库。
- 恢复会话不代表连接已解锁或网络客户端仍存在；未记住密码的连接仍需按原流程解锁。
- 输入修改串行自动保存；显示“保存中/已保存/保存失败”。只有宿主确认写入成功的状态才称为持久保存；强制退出时尚未确认的最后输入不能承诺已落盘。
- 正常连接切换先处理待保存修改，页面导航/组件卸载不应销毁保存队列。不能只靠卸载回调发一个不等待的 RPC。
- AI 已完成轮次在宿主写入目标工作区后再返回；离开页面不应丢失已经完成的回复。运行中的任务在宿主重启后不能显示为仍在运行或成功。
- 加载、保存、查询和 AI 请求都绑定发起时的目标身份与查询版本；旧响应只能更新其原目标，不能覆盖新连接或新查询。
- 保存使用版本/修订校验；多个窗口冲突时不静默覆盖其他窗口。AI 轮次具有去重标识，避免重试造成重复记录。
- 本次只恢复工作区，不把每个连接改造成长期共用的原生模型会话；保留现有“历史摘要作为上下文、用户手动应用并执行”的安全边界。

## 8. 模块职责

- 共享契约/纯规则：分页与工作区输入、输出、限制和规范化规则。
- 宿主存储模块：固定路径、白名单、容量、原子写入和修订，不调用模型或数据库。
- 现有数据应用服务：按已保存连接解析身份，组合工作区读写、AI 完成提交及查询；在现有 Remote 中登记页面所需方法。
- 数据驱动集成：SQL 只读分页和准确的后续页信息，保留各来源现有保护。
- 数据查询界面：工作区水合/保存状态、目标与版本隔离、固定结果视口与分页交互。不要把其他离线工具整体改成持久化。

## 9. 验收与证据

必须先建立能够捕获原症状的回归，然后实施并复验：

1. 连接 A 输入需求、获取 AI 回复、编辑 SQL、选择对象并执行；A → B → A 后逐项恢复且 B 不含 A 的内容。
2. 离开工具页返回、切换工具、刷新浏览器后恢复；新宿主进程读取同一资料目录也能恢复，不能只测同一进程 Map。
3. 重命名、密码轮换、重复添加相同目标仍恢复；同一 ID 改库/账号、安全上下文或资料目录后隔离。
4. 超过 200 行的确定排序查询可进入 201 行以后的结果；无跳行/重复；已有 LIMIT/OFFSET 不被突破；零行仍保留列；页大小变更正确重置。
5. 测试字节上限、长单元格和不足一页，确保内容截断不冒充下一页；失败不自动重试，不误标成功。
6. 验证延迟加载、保存冲突、旧查询/AI 回复、断开和切换后的响应不能覆盖别的目标。
7. 检查工作区文件不含表单密码/密码密文，未进入通用快照/导出；恢复不会自动执行 SQL；历史结果有时间与标识。
8. 浏览器覆盖明暗主题、窄屏与缩放，测量结果视口固定高度、内部横纵滚动、表头固定、分页栏可操作且整页不横向溢出。
9. 执行相关宿主、前端、布局回归，以及类型/架构/构建检查。真实数据库验证与合成协议测试的结论分开记录。
10. 在当前 GUI 实际验证前先核实插件加载来源和构建/热更新机制；不启动替代服务器冒充当前 GUI，不将未核实的热更新或重启验收称为完成。

## 10. 明确不做

不改数据写入权限；不增加自动执行 SQL；不提供完整结果集离线归档；不自动获取总数；不新增 ES PIT/search_after 或 Redis 通用分页；不做通用工具箱持久化、跨设备同步、连接管理重构或无关 UI 美化。
