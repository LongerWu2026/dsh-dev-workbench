# 多 AI 对话本地历史管理

历史入口从长下拉框改为可展开的搜索列表，每页10组，按最近更新排列。搜索标题、原问题、本地修订、回答正文、附件名和厂商；多个关键词可以组合。本地搜索不请求模型或厂商官网。

支持重命名问答、编辑本地问题和原有的回答编辑。问题修订保存在独立的显示字段，原问题继续用于官网回答归属与只读恢复采集；复制对比报告使用本地显示文字。回收站、修订和版本信息随本地业务数据保存、导出与导入。

删除前显示名称、轮次与影响范围，确认后移入回收站；可恢复原ID和全部问答。回收站的永久删除还需要单独确认，完成后不能通过回收站恢复。两种删除均不删除官网对话、登录状态或已存为知识的内容。没有批量自动清理、过期清理或退出官网动作。

保留现有100组/300轮总量限制，回收站记录也计入；达到上限后可先导出备份，再按需在回收站确认永久删除。未完成采集或已填入待发送的记录必须先停止操作；停止不撤回或清空官网已有内容。版本检查拒绝覆盖其他窗口的新修改。旧版宿主未声明历史协议时，搜索仍可用，写入按钮禁用并提示重新加载工作台组件。

## 实现与验证

- Client：`history.ts`负责本地索引与排序，`HistoryManager.tsx`负责搜索、分页和确认流程，`QuestionEditor.tsx`负责本地问题编辑；`WebAIPage.tsx`组合现有问答及内嵌官网。
- Host：`web-ai-history.ts`只修改本地记录，提供版本校验、回收站与修订；新增两个 Remote 接口。原有采集服务拒绝对回收站内容继续提交或回写会话地址。
- 原版 Harness：37组历史中按回答 `PDF-742` 搜得2组；本轮合成记录重命名为“附件验收｜PDF 与 Word”并保存，本地问题修订持久化，官网原问题及2轮记录保留。删除确认范围及取消通过，未删除现有历史。
- 真实删除、恢复、永久删除、未确认拒绝、并发冲突、运行中保护和迁移正常化在临时合成数据中验证，不使用用户历史做破坏性测试。

最终工程结果与脱敏实机记录见[验证证据](evidence/web-ai-local-history-2026-10-29.json)。

`pnpm build`、`pnpm check`、`pnpm test`、`pnpm test:layout`和`git diff --check`均通过。Host网页业务54项、Host冒烟240项、React159项（含历史组件6项及页面接线回归）通过；117个布局场景包含800/360宽度、明暗主题、长历史名分页及编辑对话框。源码153个模块无数字前缀、导入循环或已检测的越层依赖。

## 2026-10-30：确认按钮与批量删除

历史管理弹窗统一使用「取消」「确认」，位于弹窗独立底栏右侧，正文过长时滚动正文，底栏保持可见。移动端打开历史管理时收起展开的会话列表，避免矮窗口中列表挡住管理区域。

列表支持逐项勾选、「全选本页」和跨页累计选择，显示所选组数；搜索或切换历史/回收站时清除选择。点击「批量删除」后展示组数、轮次和全部名称，再次确认才移入回收站；回收站的「批量永久删除」同样单独确认。取消不写入，失败保留选择与错误。批量请求通过同一历史管理接口，在一次本地提交内校验全部ID、版本、采集状态和回收站状态；任一校验失败，整批不写入。批量接口需加载更新后的Host代码。

本轮验证：`pnpm build`、`pnpm check`、`pnpm test`、`pnpm test:layout`、`git diff --check`通过；网页业务60项、React318项（含历史组件及移动入口11项），通用布局153项通过。额外执行 `node plugin-tests/layout/web-ai-history.mjs`：800/360宽、600/320高、明暗主题共8个浏览器场景通过，检查了按钮顺序、底栏右对齐、窄矮窗口可见性、取消不写入、批量删除及批量永久删除。报告与截图在 `/tmp/workbench-history-bulk/`，全量日志在 `/tmp/workbench-history-bulk-test-final.log`。本轮未删除真实问答或操作官网账号，删除链路使用临时工作台数据与合成浏览器记录验证。
