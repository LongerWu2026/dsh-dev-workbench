2026-10-31。原 Agent 中心改为「研发任务」，放在顶部第二个一级入口。原办公流程与手工执行记录保留在「办公与历史」，没有删除原业务数据。

## 已实现的路径

1. 「连接与工程」配置 Linky CLI、已登录 profile 与工作空间。检查登录读取真实身份与空间列表，不向浏览器返回 token。本人工作项按单一类型每页50条读取，有后续页时继续加载，支持按需求号、缺陷号或 UUID 查询。
2. 选择「研发协作」已有工程，创建独立 Git worktree 和分支。基于工程当前提交，不包含也不重置成员未提交改动。工作区根目录必须在 Git 工程之外。同一未结束工作项复用已有任务和专属 Harness 会话。
3. 可选择 Linky 研发智能体，保存角色和技能正文快照。普通 CLI 的正文读取不等于完整资源包已准备；引用资源缺失须报告。Linky 原生任务仍使用其 daemon 准备的角色、技能目录和知识上下文。
4. 一次启动后，宿主依次运行分析、开发修复、配置的真实测试命令和独立会话中的 AI 审查。退出码非零、输出截断、模型异常、非正常轮次结束或用户暂停都会停止推进并保留原因。宿主重启后中断记录显示为暂停，不会默默重新执行。
5. 到人工审查暂停，显示累计完成、剩余阶段、原生会话、实际差异、真实测试退出码和 AI 审查意见。支持打开 Harness 开发／审查会话、补充开发要求、退回后继续原会话。
6. 人工批准绑定当时的 Git HEAD、跟踪文件差异与未跟踪文件字节。代码变化后批准失效，必须重新测试与审查。确认回写后调用 Linky 评论接口保存结果和会话编号。

本地任务状态与 Linky 业务状态独立。评论回写不代表代码已经提交、MR 已合并、缺陷已关闭或部署已完成；这些业务节点没有自动跳过。回写按钮属于外部写入的明确确认入口。

## 正式 CLI 适配模块

- 源码：`src/cli/harness-linky.ts`；构建：`bin/harness-linky.mjs`；npm bin：`harness-linky`。
- Linky 固定 Codex provider 的 `app-server --listen stdio://` 输入转为官方 Harness ACP，不启动或依赖真实 Codex。
- 支持版本与模型探测、初始化、创建／恢复会话、文本轮次、命令事件和取消。未知方法、非文本输入、越界目录、未知模型明确失败。
- 从 Harness ACP 的模型配置核实实际模型；模型不一致时使用标准 `session/set_config_option` 选择，无法核实或路由有歧义时拒绝执行，不静默替换。
- `developerInstructions` 及 Linky 准备的技能目录交给 Harness。Linky scoped token、知识票据保留在原生子进程环境中，不复制到配置、提示、前端或追踪文件。权限请求不会由适配器自动批准。
- 仅允许配置的工作区根目录，默认只读验证；「允许在工作区开发」需要在设置中明确选择。当前不自动启动 Linky daemon，不自动接收账号全部工作空间任务。

配置保存在当前 `DSH_HOME/storages/dev-workbench/development/config.json`。任务与原生适配器记录分别存于 `tasks/`、`native-runs/`，使用独立文件和原子替换，权限0600。它们独立于旧工作台 state.json，当前旧迁移／备份导出不会包含这些新文件，应连同 development 目录一起备份。

使用时先 `pnpm build`，再从页面复制实际的 `LINKY_CODEX_PATH` 和 `HARNESS_LINKY_CONFIG` 导出语句到启动 Linky 的同一终端。这两个变量不是 Linky 服务端的自定义 provider 注册接口。现有 daemon 若未继承变量，必须在确认其接单范围后重新启动；本次未自动重启它。Linky 当前版本会扩大 watched workspace 范围，因此没有提供一键启动全部接单的按钮。

## 研发接口 HTTP 404 修复

2026-10-31，桌面端出现 `transport failure for /api/workbench/development: HTTP 404`。实机检查确认 desktop profile 的工作台插件链接当前源码目录，客户端已更新，正在运行的宿主没有同步注册新增接口。通过插件管理中停止并重新启用「智能工作台」组件，重新挂载服务和 Remote 描述符后，研发设置页已实际读取 CLI 路径、profile、模型、启动参数和正式适配器路径。无需修改 Linky 登录或重签名应用包。

客户端增加精确的接口缺失提示、重新连接按钮和不可用期间的操作禁用。已有快照时接口丢失也会禁用执行入口；重连恢复时保留已有设置输入。普通 Linky 登录／网络失败保留原始业务原因，不误报为宿主版本问题。新增三项界面回归覆盖首次404、已有快照后404、业务错误区分及恢复配置。

后续部署 Host 源码后须重载插件组件；仅刷新客户端不会重新注册宿主 Remote 接口。

本次修复验证：`pnpm check`、`pnpm test`、`git diff --check` 通过；界面回归29个文件、387项通过。研发集成10个场景、CLI 传输8个场景通过。最后一次实机复核期间用户切换了应用，已停止继续操作界面；此前组件重载后的配置读取已确认成功。
