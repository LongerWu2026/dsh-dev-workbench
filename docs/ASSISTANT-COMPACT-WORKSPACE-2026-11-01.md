# AI 助手会话布局与办公主题

本轮缩小固定系统入口的占用，把主要空间留给用户正在处理的事项与最新结果。消息识别、AI 资讯、知识助手仍各自保留独立会话身份；任务中心、待回复、研发任务等原有业务入口继续保留。

## 交互与数据约定

- 三个固定入口使用紧凑能力条，不再作为四个大卡片挤占工作会话列表。原“日常工作”改为可检索的“办公历史”，原会话、报告、草稿和处理记录保留。
- 从“＋工具”选择日报、周报或回复对象，先打开对应主题，再明确生成；重复进入优先恢复原成果，不自动重复执行。日报按北京时间日期建立主题；周报按实际近七日范围建立主题。相同范围恢复同一逻辑会话，不因打开工具或查询列表创建原生模型会话。
- 批量回复草稿按排序、去重后的回复对象建立稳定主题；单条回复仍进入对应待回复会话。已有产物保留原归属，不复制或归入另一主题。
- 历史报告可以继续讨论。跨日期重新生成应从工具选择当前报告，不把当前日期的数据写进历史日期主题。日期校验在实际状态写入队列内完成，使用同一次时钟采样准备报告，覆盖排队期间跨午夜的情况。
- 工作会话支持置顶、搜索和需要处理筛选。摘要来自已有回执、业务状态或执行结果，读取列表本身不运行 AI。
- 会话栏支持折叠并记住偏好；切换会话继续保留各自输入。标题区集中状态和上下文操作，其他操作放入“工具”。
- 对话优先展示当前进度和最近结果，历史按日期收起，长成果可以展开。仍保留规则或 AI 识别来源、识别到的指令和实际执行回执。
- 忙碌自动回复作为工具设置，查看设置不启用功能；明确设置和 AI 确认沿用现有规则，回执归当前会话。

## 验证范围

隔离测试验证主题重开、上下文归属、参数约束、旧历史兼容、会话置顶及交互布局。真实客户端验证限定为重载现有本地插件、查看历史和界面操作；不发送企业消息、不开启忙碌自动回复、不执行真实研发任务。

已验证的结果：

- `pnpm build`、`pnpm check` 通过；236 个源码模块的类型、架构、构建产物一致性及语法检查通过。
- 最终 `pnpm test` 完整通过：全部 Host 回归与 32 个 UI 测试文件、498 个 UI 用例通过。
- 主题后端测试 25 项通过，包含相同主题恢复、绑定参数约束、应用重开、旧历史兼容、待处理与运行状态、230 个会话的单次日志快照读取，以及排队跨午夜校验。
- 助手与忙碌回复目标 UI 测试 56 项通过；覆盖置顶期间切换会话、过期响应隔离、主题读取、折叠恢复、历史展开保持、待确认/失败内容可见、完整原文复制和原有操作保护。
- 助手桌面/窄屏、亮暗主题布局 80 项通过，页面错误 0、横向溢出 0。通用页面布局另有 189 项通过。
- 已通过客户端界面停用并重新启用当前工作区链接的插件组件，确认恢复“运行中”。实际打开 AI 助手，三个固定入口位于紧凑能力条，办公历史位于工作会话列表；原有处理记录按日期收起，可展开查看报告、回复草稿及完整内容。
- 实际查看“＋工具”菜单，日报、周报、批量回复草稿、待办处理方案、自动回复设置入口均可达。验证结束已关闭菜单，停留在办公历史；未生成真实报告、采纳草稿、发送消息或开启忙碌自动回复。

本地证据位于 `.tmp/assistant-compact-workspace/`：`check.log`、`full-test-final.log`、`target-ui.log`、`layout.log`、`report.json`、`general-layout.log` 及布局截图。`full-test.log` 为测试入口尚未适配完的首轮记录，最终结果以 `full-test-final.log` 为准。
