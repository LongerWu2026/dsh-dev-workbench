# 普通对话工具记录展示修复

## 当前展示规则（后续修正）

用户明确要求普通聊天不展示工具日志：`chat:*` 现在完全隐藏“工具执行记录”及原始输出，保留回答、失败状态和知识引用。专用事项会话继续默认折叠日志。后文“普通聊天默认折叠”的方案是此前阶段，已由本节替代。

无最终文字答复时改为“本轮未返回文字答复，请在原会话查看执行状态。”；兼容此前缓存的提示，避免引导展开已经隐藏的入口。原始工具事件和调用能力保留。

验证：构建与类型/架构/构建一致性检查、37 项轮次投影测试、110 项助手界面测试、18 组布局检查通过。布局覆盖普通聊天无工具入口、专用会话折叠/展开、360/640/1280px、明暗主题及草稿保留。日志为 `/tmp/workbench-plain-chat-clean-*.log`，布局报告为 `/tmp/workbench-assistant-tool-activity/report.json`。

原版 Harness 实机已核对用户“查询当前目录技能数量”会话的截图对应回答：原“工具执行记录 · 2 项”入口消失，原回答、“知识依据 · 1 个片段”和“已回复”仍在。仅打开既有记录，未重新提问。

## 原因

普通目录查询实际调用了 Harness 终端工具。助手轮次投影将所有原生工具都放入 `commands`，界面又将其统一渲染为“识别的命令 / 已识别的操作”，因此正常问答后展开了终端目录输出。它并非云之家消息识别。

## 实现

- 宿主根据真实工具名和现有工作台操作映射，增加 `kind: business | tool` 来源标记；不依赖模型回答文字猜测操作。
- 原生终端、文件等工具由 `AssistantToolActivity.tsx` 单独展示为默认关闭的“工具执行记录”，按需展开查看名称、状态和原始文本。旧记录兼容已知工作台操作和规则操作，不迁移原始历史。
- 普通对话使用“正在回复 / 已回复”文案。没有最终文字答复时明确提示并显示“已结束”；失败和中断仍保留真实状态。
- 真正的工作台业务操作继续保留操作、结果和确认卡；执行、授权、重试逻辑不变。混合调用时工具记录与业务操作分别展示。
- 长输出内部滚动、换行，使用当前系统主题；输出通过 React 文本节点显示，不执行返回的 HTML。
