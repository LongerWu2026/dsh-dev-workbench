# AI 助手事项、原生会话与工作区映射

本轮修复“查看已有研发记录，继续说话却创建未分组会话”的行为，并在会话列表和对话顶部显示事项来源、真实工作区及当前 Harness 会话。

## 新建与恢复规则

| 操作 | 原生会话行为 |
| --- | --- |
| 打开事项、切换页面、刷新或恢复历史 | 读取已有绑定，不新建 |
| 在已有普通 Harness 聊天中继续 | 使用该聊天 ID，忽略旧索引中的错误 activeId |
| 待办、待回复首次需要 AI 对话且没有绑定 | 建立一次原生会话，保存后持续复用 |
| 用户明确点击“新建对话”或“为当前事项新建会话” | 按所选事项及可信项目目录新建；原历史保留 |
| 研发事项继续对话 | 默认恢复研发主会话；旧助手分叉保留为可选历史，不再自动成为主会话 |
| 选择历史会话 | 持久保存明确选择，后续读取与发送使用相同 ID |
| 审查、历史执行记录或正在执行的研发会话 | 明确显示原因；可切回主会话或到研发页处理，不静默另建 |
| 创建成功但归组或读取失败 | 保存已经返回的原生 ID，重试恢复原会话 |

同一真实目录复用同一个 Harness 工作区，不同事项仍有各自独立会话。路径只来自保存的项目与研发配置，不接受聊天提供的任意目录。不带项目绑定的普通会话明确显示“无工作区”。

工作区注册记录、事项配置与原生会话实际目录冲突时，保留原会话和归组，阻止在错误工程中发送。已恢复但尚未进入宿主缓存的会话同样检查。旧会话和业务数据不删除、不按相似标题合并。

## 界面变化

- 会话行和标题标注待办、待回复、研发、资讯、知识、报告或普通对话。
- 显示已绑定、待绑定、无工作区或不可用状态，完整目录保留在提示中。
- 当前 Harness 会话和历史选择移出“更多”菜单；原生打开按钮先选择准确 ID，再切到 Harness 面板。
- 只读原因与切回主会话入口可见，切换保留输入。窄屏长标题截断，不遮挡操作按钮。
- 新会话使用事项标题或真实用户问题命名，已有自定义标题和研发主会话名称保留。

## 验证

本轮使用隔离 Host 与合成浏览器数据验证身份、工作区和发送目标，不运行真实研发步骤、不发送企业消息。

验证结果：

- `pnpm build`、`pnpm check` 均通过；类型、237 个模块的架构约束、构建产物一致性和语法检查通过。
- `pnpm test` 全量通过，包括原生映射 20 项、工作区 25 项专项检查及前端 32 个文件的 507 项测试。
- 助手原有布局 80 个场景、新增会话映射布局 24 个场景均通过。覆盖浅色、深色、窄屏和 360×360 小窗口，检查标题、输入框、历史选择、只读提示与草稿保留。
- 已重载本地插件，在真实客户端核对同一研发事项：原研发主会话、工作区及已配置的工程目录保持一致；实际编号、工程名和本机路径不公开。
- 切换审查记录后，显示原独立审查会话与只读原因；点击“切回主会话”恢复原研发会话，原生打开后绑定不变。

客户端验证限于重载、阅读历史、切换和跳转；真实发送与创建故障重试由隔离测试覆盖，本轮未发送真实模型指令或执行研发步骤。证据目录：`.tmp/assistant-native-binding/`，包括 `check.log`、`full-test.log`、`layout/report.json`、`compact-layout/report.json`。
