# 私聊待办直接回复原会话

采用在待办内直接回复的方式，不把任务切换为待回复。任务处理和沟通状态分别维护；发送消息、保存草稿或标记已回复均不完成待办，也不改标题、截止日期等业务字段。

## 使用与边界

- 列表操作区提供“回复原会话”按钮；看板和待办编辑区同样可用。
- 仅原来源可以核对为云之家私聊、且具有会话/消息/账号定位的待办提供入口。本人发出的消息、手动待办、群聊或缺少定位的来源不冒用该通道。
- 打开时复用原来源已有回复和草稿；旧任务没有回复记录时建立一条非活动沟通记录（不需回复/已转待办），不增加待回复义务。重复或并发打开不会重复创建记录。
- 可以直接输入、用现有模型生成、保存或复制草稿；真正发送之前仍要核对原会话、发件人、原消息、发出时间和正文，并点击确认发送。
- 私聊只发送正文，不自动@对方或引用原消息；底层沿用已有CLI发送和账号校验路径。群聊原有引用回复路径不变。
- 成功后更新沟通记录，保存发送正文、时间和回执；发送正文随预留冻结，不会因后续编辑草稿而失真。待办保持原状态。
- 已发送、正在发送或结果不明确的原消息继续阻止重复发送；失败保留草稿和任务状态。此实现不新增同一原消息多轮重复发送能力。
- 服务端在发送前及持久化发送预留时重新校验任务与原消息关联，不能仅凭前端传来的taskId绕过已处理检查。准备入口不作为Agent后台发送工具。
