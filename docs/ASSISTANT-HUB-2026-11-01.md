# AI 助手统一入口

## 目标与保留范围

保留今日简报、任务中心、待回复、研发任务、资讯、知识空间和智能办公的原有入口。AI 助手提供同一份业务数据的对话入口；页面修改和对话修改必须互相可见。

## 会话

- 固定系统入口：消息识别、AI 资讯、知识库。入口身份保持稳定，不随后台模型会话恢复或更换而变化。
- 工作会话：待办、待回复、研发事项、资讯、知识条目和自由对话。再次进入恢复关联历史，不按标题猜测归属。
- 读取、打开、刷新不会自动启动识别、发送消息或执行开发。首次发送才按需创建交互会话。
- 后台结构化识别会话与自由交互分离，已有后台消息和实际业务结果在统一入口中关联显示。研发通过独立作用域继续原流程。

## 数据与操作

- 进度来自持久作业；业务状态来自原业务服务；历史从真实会话、作业及变更记录读取。
- 识别继续、重试失败、获取新消息、刷新进度分别执行，不把查询当作重跑。
- 简单且明确的待办状态操作可以直接落库并返回回执。模型推测不能作为已完成或已发送的证据。
- 发送回复、删除知识、确认修改知识等操作先给出目标和预览；确认绑定原对象及版本，重复确认不能重复执行。
- 研发保留工作区、测试、自动审查和人工审查约束。现有 Linky 回写是结果评论，不代表关闭工作项、代码提交或发布。
- 多事项和历史会话必须隔离；切换后的旧响应不能覆盖当前页面。

## 验证要求

- 固定入口只读打开、旧历史恢复、不同事项隔离、后台进度与真实结果。
- 页面更新后会话读取最新状态；会话操作后原页面状态一致。
- 删除/修改确认的版本冲突、重复确认、取消、失败回执。
- 刷新和恢复不重复执行；研发约束不绕过；不触碰真实外部消息或工作项。
- 桌面、窄屏、亮暗主题下列表可折叠，长结果和确认预览不溢出，输入和发送可达。

## 实现与验证

- Host 统一入口为 `assistantHub`，原有 Remote、页面入口和旧 Host 助手兼容路径保留。
- 本地会话索引、原生执行区间和确认回执独立持久保存；不会复制成另一套业务任务。
- 历史记录缺少旧执行的逐轮关联时明确提示，仍可通过“后台历史”读取现存原会话，不猜测绑定。
- 知识确认、历史会话与工具执行按项目和账号范围核验；质量评测和办公摘要不会混入业务识别或资讯历史。

## 系统消息默认显示修复（2026-11-01）

问题有两层：自动调度和旧同步接口绕过持久作业，缺少执行与会话关联；固定会话的主时间线只读互动消息，后台记录需要额外打开历史。

- 固定消息识别、AI 资讯会话默认投影已明确归属的真实后台输入、结果及错误，与用户讨论按时间合并。旧记录无需补建作业即可显示，不猜测未登记会话的归属。
- 显示“系统提交 / 系统结果 / 系统失败”；结构化协议转成可读摘要，原始内容可展开。主时间线原文限 4000 字并明确节选，完整内容仍可从后台历史读取。
- 自动执行和旧同步接口在实际有待处理项时创建观测记录；现有队列任务复用原 ID。保留原返回值、单飞、顺序与冷却；观测记录在重启或迁移后不会被重新入队。
- 打开/刷新只读，按原生 sessionId + seq 去重与分页；按序号增量解析、合并并发冷恢复。自由追问携带最近真实系统消息及来源，不注入原结构化批处理会话。
- 旧识别的实际落库结果也在关联结果中显示，不要求事后伪造运行 ID。

## 提取结果可见与原事项修正（2026-11-01）

- 消息识别固定会话默认展开“提取结果”，直接读取与真实识别来源关联的已保存待办、待回复。提供类型、搜索、每页 6 项和来源内容；未登记建议仅显示待确认数量，仍使用原确认入口。
- 点击“在对话中修改”留在同一固定会话，附加准确事项引用并保留输入草稿。Host 重新读取原事项，拒绝无关、已归档或已失去来源关联的引用，不信任浏览器提供的正文。
- `analysis.results` 查询实际结果；`analysis.updateResult` 更新原事项并记录修改前后，不通过重新识别或创建重复事项实现修改。待办沿用人工字段保护，待回复仅允许修正摘要和阶段；原消息、收件人及发送链路不变。重新识别保留人工修正。
- 固定交互会话连续发送、冷恢复、失败重试和并发首次发送都沿用持久身份。首次交互按需创建一次，发送前设置清晰的原生标题“消息识别 · 助手”；历史读取不创建或改名。后台结构化执行继续独立承载。
- 本机只读投影核对读取到 111 项已保存结果（55 项待办、56 项待回复），首页 6 项均有来源。该核对没有触发模型、重识别或修改业务数据。

后台会话根因补查（只读）：同名消息识别原生会话 125 个中，124 个曾出现 `reasoning_content` 历史重放错误。旧恢复逻辑在新会话首轮成功后立即清除故障计数，导致第二轮再次失败时又新建。当前后台会话已经成功完成 7 轮，最近两个真实作业复用同一会话的连续区间；侧栏“刚刚”为最近活跃时间，不是创建时间。没有证据把当前稳定归因于模型切换。

客户端已重载核验：结果区直接显示 111 项（55 待办、56 待回复）及每页 6 项；“在对话中修改”保持固定消息识别入口、准确选中 1 条并填入提示。清除验证草稿及引用后发送按钮恢复禁用，没有发送模型请求或修改真实事项。另将“查看本轮/这次提取结果”限制为最新真实识别作业；没有轮次关联时明确提示，不把全部历史当本轮。

后台恢复保护：按实际原生请求的 provider/model、账号及规则范围持久记录兼容恢复。首次失败可换一次会话，新会话首轮成功保留保护，成功续轮后才清除；同类错误复发立即使用现有模型暂停机制，剩余消息不丢失且不自动空转。独立进程重启保留保护；模型切回需在当前会话重新通过续轮；明确的取消/创建失败仅回滚本次未绑定的预留。普通 400 与原有会话丢失恢复不受影响，不删除旧历史。
