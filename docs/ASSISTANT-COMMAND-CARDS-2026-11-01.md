# AI 助手消息卡片与规则接续

## 用户可见行为

每条回复以结果正文为主。“规则”或“AI”作为卡片底部的轻量来源标记，有实际操作记录时增加“指令”标记。原始操作名称与参数收进“指令详情”，不再把 `development.continue` 等内部名称直接作为聊天内容。

识别来源与执行状态分开：规则识别到操作，并不代表操作一定可以执行。研发任务处于人工审查等不可启动阶段时，卡片说明当前原因及下一步，不把状态保护误报成规则未识别。

## 规则与 AI 的边界

- 明确、单一、作用域内的常用指令优先使用规则。
- 规则未命中、含义不明确或纯识别阶段异常时，自动接续 AI，保持同一条处理记录及原生会话。
- 疑问、否定、多动作及不明确的确认不能被宽泛规则直接执行。需要澄清的请求保留工具执行约束。
- 已命中指令并进入执行后，错误保留实际结果和原因，不自动让 AI 重复执行或绕过人工审核。
- “改用 AI 识别”仍用于重新理解原话，属于建议，不重复执行之前的操作。
- 不按标题合并或重建已有会话，不修改历史业务结果。

只读问句（例如“查看进度？”“这次提取了什么”）仍可读取真实结果；疑似写入的问句才进入澄清保护。宿主缺少仅理解所需的工具拦截能力时，直接显示本地澄清说明与“待你补充”，不冒称已调用 AI。

## 验证

验证结果：

- `pnpm build`、`pnpm check`、`pnpm test` 均通过。完整前端回归为 32 个文件、511 项测试。
- 后端专项：指令显示与规则识别 26 项、反馈 28 项、原生轮次投影 33 项、助手操作 45 项、原生绑定 20 项均通过。
- 规则验收包括 27 种常用明确表达、10 种歧义边界、4 种只读问句、6 种写操作疑问；覆盖同一请求不重复执行、规则异常后接续、已发生写入后回执异常不能触发 AI 重试、人工审查受阻不重启研发。
- 新消息卡片 64 个布局场景和已有助手 80 个布局场景全部通过，覆盖浅色、深色、窄屏及 360×360 小窗口。
- 已重载本地客户端组件并确认“运行中”。真实研发会话里的旧失败记录现在显示正文和底部“规则 / 指令 / 未完成”，`development.continue` 默认隐藏，展开和收起“指令详情”均可正常操作。历史记录仍保留原来的失败原因；没有重写旧业务结果。
- 核对主会话 ID 仍为 原绑定会话（编号不公开），返回原生 Harness 后未发送草稿仍保留。

证据目录：`.tmp/assistant-command-cards/`，包括 `build.log`、`check.log`、`full-test.log`、`layout/report.json`、`compact-layout/report.json` 及合成布局截图。布局验收拦截所有网络请求；真实客户端只验证阅读、展开详情和跳转，没有发送模型指令、企业消息或启动研发。自动转 AI 与执行保护由隔离 Host 测试验证。
