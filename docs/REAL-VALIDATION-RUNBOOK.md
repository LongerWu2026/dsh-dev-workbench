## 0 执行前条件

- 故障/替换/恢复使用独立DSH_HOME。桌面可在明确授权的日常账号中使用带前缀的合成包进行合并验收，先备份，不替换或删除日常数据。
- 记录 DSH 版本、插件提交、模型、时区、测试目录及连接器状态。加载最新构建；Host 变化后重启，Client 变化后刷新。
- AI 识别、后台触发和 Task 自动登记分别记录开关状态。Reply 自动建档不受 Task 的 autoRegister 控制，需纳入预期。
- 默认使用已有的授权消息样本或本地夹具。新增外部消息、邀请、表单提交或外部系统迁移需要明确授权。
- 0.2.0已修复迁移预检与提交，并通过隔离故障及新目录重启测试；真实GUI仍在独立测试目录使用复制的样本包验证。
- GUI 测试连接明确的调试目标；页面导航走查通过不能替代真实模型和数据一致性验证。

## 1 消息采集

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| M1 | 他人普通私聊，无 @标记 | 产生来源及待分析条目，保留真实会话/消息定位 |
| M2 | 群内 @本人、@他人、自聊、系统消息 | 只将约定范围内容作为新事项入口 |
| M3 | 上次游标与新消息在同一页 | 新消息不因命中游标而整页丢弃 |
| M4 | 多页、超过会话/单批上限、某页失败 | 有续采位置；成功落库前不越过边界，重复执行不重复 |
| M5 | 本人后续答复及相关群消息 | 作为上下文/更新证据，不能作为本人新交办重复建档 |
| M6 | 切换账号/组织/项目 | 来源、游标及关联不会混用；检查读取是否影响原应用未读状态 |

## 2 AI 识别与独立义务

| 编号 | 样本或操作 | 通过条件 |
| --- | --- | --- |
| A1 | 「辛苦啦」「收到通知，仅供参考」 | 不建立处理或回复义务，除非上下文另有明确要求 |
| A2 | 「接口预计什么时候能完成」 | 形成待回复；是否形成/关联 Task 取决于上下文 |
| A3 | 「明天下班前提交灰度方案，完成后回复我」 | Reply 与 Task 独立建立，期限依据原消息时间和明确时区 |
| A4 | 一条消息交办两件事 | 两个 Task 共用来源但不相互覆盖；Reply 关联正确 |
| A5 | 会议、开发、登记三类样本 | 仅提取有依据的时间、地点、交付物、登记对象；缺失留空 |
| A6 | 「周五能完成吗」 | 不把询问视为本人已承诺的截止日期 |
| A7 | 不同会话的相似标题 | 不因包含同一标题而误合并 |
| A8 | Task 自动登记关闭后分析并确认 | 处理事项停在待确认；人工确认后建档；Reply 行为符合明确配置说明 |
| A9 | 重复同步、重复确认、并发分析、JSON/模型异常 | 不重复建档；失败按条目记录，不把整批误报成功 |

## 3 后续状态与人工保护

| 编号 | 操作 | 通过条件 |
| --- | --- | --- |
| R1 | 本人回复「收到，下午看」 | 记录确认收到，尚需实质答复的 Reply 不被提前关闭；Task 保持未完成 |
| R2 | 本人提供实质答复 | 仅关闭对应 Reply，保存依据消息；不自动认定实际工作已交付 |
| R3 | 有交付证据或人工标记完成 | 只推进相关 Task；Reply 根据沟通要求单独判断 |
| R4 | 取消、代答、转交或补充要求 | 更新原义务，记录来源，不重复新建相同事项 |
| R5 | 人工改标题/期限、忽略、稍后提醒、标回复阶段后重分析 | 人工字段和判断保留，有冲突时可解释 |
| R6 | 首页及任务中心的回复操作，待回复超过 6 条 | 全部入口使用 Reply ID 和统一阶段，可浏览并处理全部待回复 |

## 4 聊天 后台与界面

| 编号 | 操作 | 通过条件 |
| --- | --- | --- |
| C1 | 在右侧助手要求创建和更新一条待办 | 工具返回真实对象 ID 与修改结果，Host 落库，页面显示同一份数据 |
| C2 | 添加/移除上下文引用，切换原生会话，重启后继续 | 会话、上下文和记录归属正确；切换会话不误称切换工作台数据空间 |
| C3 | 通过聊天维护 Reply 或知识条目 | 已提供的业务工具按统一契约执行，结果可追溯；能力缺失如实说明 |
| C4 | 通过聊天更新资讯并生成摘要 | 区分采集与摘要操作；只在工具成功及卡片更新后报告完成 |
| B1 | 开启自动化和 AI 识别，运行一轮 | 按采集→分析顺序执行一次；正常结果不产生 processed_ 等错误 |
| B2 | 后台分析同时在助手聊天 | 会话与结果按请求隔离，不混入其他轮次 |
| B3 | 断线、失败、重启、休眠恢复 | 有有限重试和恢复记录，不重复产出；不承诺进程退出期间继续工作 |
| B4 | 长模型请求期间编辑待办 | 本地短操作可完成，草稿不被后台刷新抹掉 |
| B5 | 模拟旧请求晚返回 | Client 不以旧 revision 覆盖新数据 |
| B6 | 关闭开关、取消待执行条目 | 不启动新任务；已执行或已提交部分有明确结果 |

## 5 资讯

| 编号 | 操作 | 通过条件 |
| --- | --- | --- |
| N1 | 无 RSS、配置关注主题 | 宿主联网能力可用时能发现带来源的资讯 |
| N2 | 无发布日期或历史文章 | 不以抓取日期冒充发布日期，不把旧文当最新动态 |
| N3 | 手动单条及批量摘要 | 四段内容写回同一条，结论有原文依据；单条失败明确 |
| N4 | 后台摘要及部分缺段 | 新条目自动进入摘要，缺段按规则补齐；重复运行不重建 |
| N5 | 来源不可访问、模型失败、重复文章 | 记录具体失败与重试状态；URL/事件去重，相关性排序可解释 |

## 6 迁移与恢复

以下步骤在独立测试目录执行，完整记录目标DSH版本与样本包。

| 编号 | 操作 | 通过条件 |
| --- | --- | --- |
| D1 | 导出完整样本数据 | Reply/Task/Source 等业务集合、ID 和关联完整；队列/游标策略明确 |
| D2 | 对不同内容迁移包执行 dryRun | 文件字节、内存状态、revision 不变；只返回预览和问题 |
| D3 | 校验损坏、重复 ID、悬空引用、不支持版本 | 拒绝导入，原数据不变；各类错误可定位 |
| D4 | 模拟备份失败和落盘失败 | 不返回成功；原文件与内存可用，不出现半提交 |
| D5 | replace、merge 与路径映射 | 替换范围明确，同 ID 冲突符合策略，人工修改按约定保留 |
| D6 | 导入到新目录后重启加载 | 数量、ID、Reply 与 Task 关系、来源及状态一致 |
| D7 | 恢复备份 | 失败可恢复；成功后 Client 同步正确，不被较低修订号卡住 |
