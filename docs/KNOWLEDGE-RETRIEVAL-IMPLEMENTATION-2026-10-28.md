# 知识检索整改：实现与验证

日期：2026-10-28。将[设计建议](KNOWLEDGE-RETRIEVAL-REDESIGN-2026-10-28.md)中的本地知识链路接入现有Harness插件，保留原知识ID和state.json；没有部署外部知识平台。

## 可以使用的入口

- **知识空间**：审核历史条目、维护已确认/待审核/已失效状态、项目/账号范围与有效期；导入Markdown/TXT或粘贴正文；输入问题测试召回、查看近期检索记录。
- **侧边助手**：默认自动检索，展开“知识设置”可切换仅知识库/关闭及项目/账号范围。短追问使用同会话上次检索主题，无须再次手动添加长资料。
- **回答来源**：显示本轮实际送入模型的片段，点击读取原文、版本和知识正文行号。已更新/归档/失效的旧引用不能偷换成新正文；无效引用、缺少引用或回答期间资料失效给出提示。
- **Agent工具**：`workbench_knowledge_retrieve` 与 `workbench_knowledge_read`。原统一搜索保留资料发现用途，归档和失效知识不再从该分支返回；候选内容仍可用于管理发现，但不能进入默认回答检索。
- **办公流程**：回复草稿和待办方案由Host在模型调用前检索知识，冻结本次证据；模型生成后及采纳草稿前重新核对知识有效性。产物可“存为候选知识”，确认后才成为默认知识。

日报的业务进度仍取自Task/执行记录，不把规范或旧笔记当成本周已完成事实。

## 默认本地检索

实现中文字符组合、英文/接口标识符拆分、少量显式同义词扩展、BM25相关性排名和段落/标题分块。按项目、账号、审核状态、归档和有效期过滤，再去重选择片段；默认至多5个，最多8个，总正文预算12000字符。手动引用与知识合计超过48000字符时拒绝，而不悄悄截断。

按正文及元数据内容哈希生成片段版本；索引是有界内存派生缓存，更新后自动重建，重启可重建。迁移包包含知识状态、范围、来源、正文及最近100次检索记录，不迁移内存向量缓存。旧版本迁移包缺少检索记录时兼容保留。

这是个人工作区内的逻辑范围隔离；现有插件的完整快照仍面向同一个本机用户，不应宣称已经实现多人服务器的权限系统。

旧知识默认待审核；模型工具新建/修改的内容也是候选。用户在知识页显式确认后参与自动检索。只收藏URL、没有正文的条目不会被当成已经读取的文档。

“仅知识库”无命中时不创建多余模型轮次；有命中时限制会话工具调用，避免悄悄转成联网或其他工具补充。工具限制跨插件热重载从持久检索记录恢复，轮次结束释放。

## 可选语义检索适配

默认不请求向量服务，也不新增模型配置或下载模型。实现了可选的Ollama `/api/embed` 协议适配器：

- `AWB_EMBEDDING_URL`：显式配置的完整接口地址，例如本机服务的 `http://127.0.0.1:11434/api/embed`。
- `AWB_EMBEDDING_MODEL`：该服务已安装的向量模型名。
- `AWB_EMBEDDING_TOKEN`：可选Bearer凭据，只从进程环境读取，不保存到业务数据/迁移包。

这些变量必须由启动Harness的环境提供；本轮未修改机器启动环境。配置前请先确认服务及模型可用。协议依据[Ollama官方API](https://github.com/ollama/ollama/blob/main/docs/api.md)与[官方Embedding说明](https://github.com/ollama/ollama/blob/main/docs/capabilities/embeddings.mdx)。

语义检索只对当前已过滤范围生成向量，正文版本/模型/端点变化会使缓存失效；请求8秒截止、禁止重定向、不允许服务静默截断。当前至多200个片段参与向量检索，超出时保留本地检索并提示缩小范围。采用关键词与向量结果的RRF融合；没有额外引入收费重排模型。向量服务失败时保留本地命中，若本地也未命中则明确显示检索异常。

适配器经过隔离契约/向量排序/缓存/错误降级测试。日常Mac未配置该提供者，本轮真实模型验收使用本地全文检索，不能据此宣称真实Embedding模型检索质量已验收。复杂PDF/Office解析及RAGFlow部署没有实施；当前资料接入范围为笔记、片段、Markdown/TXT与粘贴正文。

## 验证层级

规定检查为 `pnpm build`、`pnpm check`、`pnpm test`、`git diff --check`。工程断言包括中文同义问法、项目/账号隔离、候选/过期/归档过滤、旧版本拒绝、仅知识库无答案不调用模型、聊天两条路径、办公证据快照、幂等、引用审核、迁移和热重载限制恢复。

新增30条标注**合成**问题，包含同义表达、接口标识符及无答案；评测的是相关片段能否被召回，不是30次真实模型回答，也不代表实际业务总体准确率。千条合成知识检索压力检查单独记录。React实际点击验证检索→读原文、审核/导入、模式/范围和候选经验；独立浏览器覆盖十页、深浅色、360–1280宽度、短窗口、8个上下文及原文弹窗。

真实Harness使用本轮创建且明确标记的验收资料，通过已有模型验证不添加手动引用的问答；更新独立事实后同会话冷恢复追问、旧引用拒绝、仅知识库无答案及办公流程分别核对。最终计数、构建哈希和每项实际状态见[脱敏证据](evidence/knowledge-retrieval-2026-10-28.json)，不得将工程或合成测试混写为真实业务通过。

## 最终结果

- `pnpm build`、`pnpm check`、`pnpm test`、`git diff --check`通过；125个源码模块无数字前缀、无循环/检测范围内越层引用，78个Remote端点、16个Agent工具。
- Host240、可靠性56、批量32、办公25、办公工作流15、知识检索27、历史归档12、生命周期244、同模块挂载202、React50及十页渲染通过。
- 30/30标注合成召回/无答案问题通过；千条短知识夹具约11ms，不外推到复杂PDF或超大语料。
- 独立浏览器95项布局检查通过，零页面错误；发现并修复了知识设置挤压8个上下文输入区的问题，设置区改为可收起。
- 原生已有模型在零手动引用下答出独立事实“青鹭-7429”；原文更新后，同会话冷恢复短追问答出“青鹭-7430”和新版本引用。旧引用显示版本已更新。
- 仅知识库无答案本地返回；原生待办方案使用了新版知识，产物依据包含该知识片段。产物存为候选，未自动升级成可信事实，也未自动完成关联Task。
- 本轮合成原文已标为失效，再检索为0条，未审核的派生产物未替代它进入回答。保留明确命名的验收条目/任务与历史产物供回看，未删除既有业务数据。

待办54–56、58按上述本地范围核销；57的真实向量提供者及复杂文档仍保留。原有待办18的跨账号、多日及完整系统休眠矩阵也没有被本轮测试替代。
