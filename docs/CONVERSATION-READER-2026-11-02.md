# 未读会话查看与向上加载历史

首页“消息概览”的会话名称可点击打开阅读弹窗，包括“显示全部”中被 AI 收起的无关会话。首次仅展示打开时快照中的未读，不预先展示历史。到顶部后继续向上滚动，每次插入更早的 10 条；历史不足时只显示实际条数，到最早消息后停止。

## 交互

- 向上滚动或触摸顶部继续下拉加载一批；连续滚轮合并为一次手势，读取期间不重复请求。程序调整滚动位置不会自动触发读取。
- 新消息插在上方，并根据原可见消息的 ID 和像素偏移恢复阅读位置。固定阅读区域、保留必要的底部空白，保证只有一两条未读时也不跳动。
- 顶部文字入口支持键盘操作；失败保留已有内容与本批进度，可重试。历史读取中途失败，只补本批余下条数，不将一次操作扩大为下一批。
- 发件人、北京时间、本人标记、未读/历史分界继续展示。关闭、切换会话或切换账号后，迟到回包不会串入。

## 接口与边界

- 仅 UI Remote：`workbench/conversationMessages` 和 `workbench/conversationRead`。只允许当前消息快照中的会话及当前登录账号，不扩展 Agent 或发送权限。
- `mode=unread` 用于初始读取与未读续读；`mode=history` 在未读读取结束后，每批最多返回 10 条历史。相同游标不能换阶段，重试重放原响应，不重复推进。
- CLI 每页最多 20 条；同页多取到的历史留在短期内存缓冲，等上滚才返回，不丢失或跳过。单请求最多读 3 个原生页面；大未读窗口自动续读，后续历史按手势加载。
- 固定快照消息头和未读数量，后来消息不会挤入旧窗口。账户校验覆盖网络等待前后；分页位置由短期 Host 阅读窗口管理，不接受任意消息锚点。
- 使用现有云之家 CLI 只读消息和受限姓名查询，不调用 AI、识别或发送。成功展示全部未读后，单独保存工作台已读位置，不改云之家未读快照、采集游标、回复或待办状态。
- 找不到锚点、可见数量不足、翻页无进展、限流均明示。消息纯文本呈现，不显示内部账号 ID 作为姓名。

## 查阅后工作台已读

- 首次未读完整展示成功后，保存当前账号、会话和打开时消息头的本地已读位置；会话从工作台未读列表移出，阅读窗口继续保留，可上滚查历史。关闭后再进入及重启后仍保留位置。
- 云之家 CLI 当前只有查询已读回执，没有设置会话已读命令，因此云之家客户端的未读红点不清除。界面用“工作台已读”和“云之家未读”明确区分。
- 待回复义务独立保留，不调用“不需回复”“已回复”或完成待办操作。待回复卡片的工作台已读标记不代表已答复。
- 后续消息头变化时，会话重新显示为“新消息”；仅展示已读位置之后的新未读，旧消息仍可逐批上滚查看。不同消息即使同秒也不会按时间误判为已读。
- 读取失败、快照消息头缺失或可见消息少于未读数量时不标读。保存失败可单独重试，不重复请求正文。关闭/切换账号的迟到消息回包不触发标记。
- 本地状态经标准化保留，写入使用原子状态队列及完整修订快照；并发旧窗口不能回退较新的已读位置。记录按账号和会话隔离，最多保留2000条，不保存聊天正文。
