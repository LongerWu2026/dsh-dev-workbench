# AI 助手修改 Linky 研发事项

在绑定研发主会话中，需求、用户故事和缺陷支持查询及修改 Linky 工作项。业务字段与本地执行状态分别保存、显示；状态变化不能代替测试、审查或人工批准。

## 操作

- `workbench_assistant_action` 新增 `development.issue.get`：按当前会话绑定的 profile、工作空间和工作项读取详情与真实可用流转，返回标题、描述、业务状态、可流转状态及表单要求。
- 新增 `development.issue.update`：支持 `patch.title`、`patch.description`、`patch.status`。明确修改直接执行，不添加一轮通用授权；状态单独提交，使用 `issue move` 走平台权限和流转校验，内容使用 `issue update`。流转字段使用 `fields`，评论使用 `comment`，不猜测用户值。
- 简单指令支持“查看当前需求可用状态”“把需求状态改为需求编写完成”“把标题改为…”“把描述改为…”。普通“标记完成”不映射为测试通过，交由 AI 查询真实状态并澄清目标。
- AI 工具只允许当前研发主会话修改绑定对象；审查/历史会话和其他事项不能代替修改。现有开发继续、测试、审查和结果回写入口保留。

## 结果与恢复

只有 Linky 回读字段与目标一致后才报告成功并更新 Harness 的工作项副本。业务更新不改执行阶段、步骤、测试退出码、批准证据或代码文件。聊天保存实际修改前后结果；助手顶部分别显示 Linky 业务状态与本地执行状态。

同一工作项并发修改被阻止，重复目标只读取。提交前持久记录待核实操作；超时、回读失败或成功响应与回读不一致时不报成功，不自动重放写入。后续先读到目标值时可恢复确认，仍不一致则提示核对 Linky 操作历史。

## 验证边界

- 本机 CLI help 已核实 `issue update`、`issue move`、`issue show` 与表单文件参数。真实只读链路通过新服务读取验证工作项详情和流转，返回 15 个状态、3 个允许流转；固定 profile/工作空间/工作项全部匹配，原本地记录字节未变化，仅执行 show 和无目标状态的 move 查询。
- 所有修改测试使用临时 profile 和模拟 CLI，不修改真实 Linky 工作项。25 项新增检查覆盖字段回读、状态流转、必填字段/评论、重复/并发提交、范围与主会话保护、回读失败恢复、状态不一致和真实测试证据保留。
- `pnpm build`、`pnpm check`、`pnpm test` 和 `git diff --check` 通过。完整前端 36 文件、610 项；Host 链包含新增 25 项、既有研发流程 69 项及助手操作/指令回归。
- 研发会话主/历史视图在浅深色与四种尺寸下验证 24 个布局场景，业务状态与本地执行状态分开展示、历史保护和草稿恢复保持有效。
- 日志保存在 `.tmp/development-issues/`。未进行真实远端修改验收，不能把模拟写入当成真实业务状态已变更。

## 反馈修复：状态标记为完成

实际会话记录证实，该原话此前规则未匹配，AI 没有调用业务工具，继续沿用历史只读说明，未提交任何状态流转。

- 补充“状态标记为完成”“标记完成”“把当前需求标记为已完成”等表达。通用完成意图先查询真实工作流状态，不猜测完成节点，不启动模型或新建原生会话。
- 查询结果在原会话保存状态选择卡片，提供真实允许流转的节点、必填字段和评论；选择具体状态后执行既有受校验的修改及回读。研发页头显示当前 Linky 状态，本地测试和审查状态不伪造。
- 研发主会话增加“修改业务状态”入口。历史/审查会话的卡片不能提交工作项修改；提交时再次检查平台当前权限、前置条件与表单。
- 查询卡片标记“已查询”，文字明确“本次尚未修改”，不会把查询成功说成业务完成。

验证：`pnpm build`、`pnpm check`、`pnpm test`、`git diff --check` 通过；完整前端 36 文件 / 611 项，专项 Host 32 项，助手操作 45 项。新增浏览器布局测试 `plugin-tests/layout/development-status.mjs` 的 8 个尺寸/主题组合通过，包含必填表单和窄屏无溢出检查。全部修改测试使用隔离数据和合成 CLI。

真实客户端已重载，原需求会话已通过“修改业务状态”入口查询并展示“需求编写完成”“需求评审完成”“已失效”三个允许流转的选项，页头仍为“Linky：待处理 · 执行：已暂停”。另以只读 CLI 复核绑定信息、15 个状态及 3 个允许流转，仅执行 show 和无目标的 move，原本地需求文件字节不变；没有进行真实 Linky 状态修改。日志位于 `/tmp/development-status-*.log`，布局报告位于 `/tmp/workbench-development-status/report.json`。
