## 1. 当前结论

优先完成「他人私聊入站/群内 @本人 → AI 判断回复与处理义务 → 登记具体事项 → 跟踪后续变化」这一业务闭环。页面、会话、采集和规则能力已有基础，不能将这些局部能力等同于自动办公目标已验收。

本盘点中的缺口已统一映射到 [待办 13–23](TODO-AI-AUTOMATION.md)，逐项含解决思路、方案、依赖和验收；整体实施架构与阶段见 [统一实施方案](UNIFIED-IMPLEMENTATION-PLAN.md)。

- `node scripts/build.mjs --check`：18 个 Host part、14 个 Client part，无顶层重名。
- `node --check index.js`、`node --check client.js`：通过。

真实 React 测试当前主要覆盖页面渲染和命令面板检索交互；不能据此宣称模型提取、真实消息全量覆盖或后台办公流程已通过。

### 真实 DSH 界面走查

- 从原生会话界面打开「智能工作台」成功。
- 首页展示待办和联网采集的技术雷达；任务中心可打开，仍为规则提取候选流程。
- 助手侧栏能打开、关闭，存在会话选择和原生会话入口；本轮未发送模型请求，不评价本轮真实回复/工具执行效果。
- 设置页可见后台采集开关、运行间隔、RSS 与联网策略、JSON 导出及备份恢复；本轮未修改设置、恢复备份或创建业务数据。
- 原有 GUI E2E 目录留有多页 30 秒超时记录。本轮未重跑该套浏览器测试，手动走查只证明上述入口可用，不代替完整自动 E2E。

## 4. 建议实施顺序

1. 补齐消息分页、游标和私聊识别，准备覆盖超页与双向消息的夹具。
2. 接入模型并实现回复/处理双维度、具体事项及来源证据。
3. 补充话题归并与后续状态更新，验证重复同步、人工处理保护。
4. 将流程接入后台任务，补进度、重试、部分失败和实际耗时记录。
5. 完成少量真实样本闭环及 GUI E2E，再扩展资讯质量、数据迁移和展示细节。

SQLite、逐 token 流式、完整原生组件内嵌及工具箱扩展可排在上述业务闭环之后。
