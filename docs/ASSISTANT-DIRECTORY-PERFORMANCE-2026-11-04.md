# AI 助手会话目录读取

侧栏的“会话列表读取较慢”来自 Client 的 10 秒读取期限，并不表示右侧模型没有结束。一次超时不能区分 Host 排队、传输延迟或目录本身的计算耗时。

## 本地证据

在临时目录复制当前 profile 的业务状态、助手索引和研发任务后测量；未修改原 profile，未启动模型或连接外部服务。目录共 16 项，研发文件 3 份。

| 指标 | 修改前 | 修改后 |
| --- | ---: | ---: |
| 每轮文件读取次数 | 93 | 7 |
| 每轮读取字节数 | 16,246,980 | 1,362,076 |
| 三次目录耗时，毫秒 | 85.8 / 64.2 / 61.8 | 13.9 / 5.9 / 5.6 |
| 同一研发文件每轮读取次数 | 27 | 1 |

这些是隔离副本的计算与文件读取结果，不代表已经测到或消除了客户端真实的 10 秒延迟。Host 的完整业务状态仍约 80 MB，其写入及传输可能带来额外负担，本次没有迁移存储或改动全量快照契约。

## 调整

- 每轮目录复用同一份研发任务和事项会话索引，目录中的绑定校验不重复读取研发文件。
- 已加载原生会话按对象与事件序号缓存标题、最近时间、首条来源特征和运行标记。目录不为判断“是否运行”构造完整对话、工具或附件内容。
- 新事件、原生重命名或会话对象替换会失效元数据缓存；显式发送和删除保留原有归属检查。
- 切换事项仅刷新当前内容，目录按自身周期更新。新建主题或会话后主动更新目录；知识范围改变仍重新读取。
- 列表轮询在上一次读取结束后再安排下一次，不累积请求。超时后自动重试，有旧目录时保持可用；真实错误与首次加载失败仍可见。

## 验证

- `tests/assistant-directory-performance.mjs`：73 个目录项、30 份研发文件、70 个合成原生会话，校验文件读取上限、元数据增量、重命名与原生执行保护、只读状态。
- 助手界面回归覆盖切换时不重拉全表、超时自动恢复、草稿和正文保留、真实错误及目录更新。
- `pnpm test`、`pnpm build`、`pnpm check`。
