# 真实账号及官网验收

用户授权使用专用测试问题和附件验收上传、每轮厂商切换及登录后仅补发未发送厂商。使用现有日常应用及内嵌官网，不读取凭据，不更改登录缓存，不接受付费升级。

## 本轮修复

- “待检查”原本代表尚未确认登录，现改为动作文案“查看登录”。明确检查到需要登录时仍显示“需要登录”。
- 厂商选择和回答更多菜单，点击外部或按 Escape 收起；菜单内部多选不关闭。
- 右上角“登录 / 官网”打开独立官网浮层，背景聊天保留且不可操作；“返回聊天”、Escape 或点击遮罩关闭。官网组件持续挂载以保留会话与采集。
- 附件补发同初次发送一样，上传时展开官网，确认提交后回到聊天，避免隐藏 guest 无法上传。
- 豆包实站会格式化全角标点和标点旁空格，原问题严格匹配因此误判成其他提问。采集匹配现统一全半角及标点旁空格，仍拒绝内容不同的问题；对已发送回答仅恢复采集，没有重新提交。
- 智谱实站登录框使用普通容器与 text 输入，新增仅限该站的手机号、短信验证码两个可见字段及登录操作联合判断；不读取字段值，隐藏表单及消息内表单不计入。

## 已观察的实站结果

测试文件：host-integration/rc5/artifacts/live-chat-20261030/workbench-live-attachment.pdf，仅含校验代号 WB-LIVE-P7Q4 和数量13。

第一轮 A：Kimi、豆包。豆包官网确实上传并回答 WB-LIVE-P7Q4,13；修复标点格式匹配后，通过“采集本轮回答”收录为 completed，没有重新发送。Kimi 官网提示“和Kimi聊天的人太多了，订阅会员可进入优先队列”，问题仍在草稿，未购买升级；其采集已停止，不把它算作发送成功。

第二轮 B：智谱、豆包，复用同一业务会话但厂商标签集合不同。豆包上传并完成回答 WB-LIVE-P7Q4,13；智谱被真实登录框拦截，状态 needs_login、submission=not_sent。

用户完成智谱登录后，实站账户积分区域与历史导航的联合识别也已补齐，且结果不包含昵称或积分值。界面显示“已识别登录”。登录后智谱仍为 not_sent，没有自动发送。

用户明确授权继续验收，点击第二轮“发送给智谱清言”，重选原PDF后点击“发送本厂商”。只在原轮次更新智谱项，最终 completed，回答为 Validation code: WB-LIVE-P7Q4 / Quantity: 13。

补发前后官网可访问性树核对：豆包A、B问题各1条；智谱B问题1条。两条豆包回答的文本、状态、更新时间、URL及采集基线在前后快照中完全一致，测试业务轮次仍为2，没有创建额外轮次。完成后的智谱补发按钮不再出现。第一轮切换豆包后，第二轮保持智谱选择。

前后证据位于 host-integration/rc5/artifacts/live-chat-20261030/before-resend.json 与 after-resend.json，均只记录这两轮专用测试数据。登录后单厂商补发、附件读取及无重复发送的本次实站验收通过。Kimi繁忙限制仍单独保留为未通过项。
