# AI 助手目录响应补充修复

## 上次测试漏掉的情况

之前分别请求目录和详情、限制冷恢复等待时间，能处理异步恢复悬空，但不能处理同步计算占住宿主事件循环。`Promise.all` 同时读取很多已加载后台历史时，恢复后的投影会连续在微任务中执行；期间新到达的目录 RPC 和超时计时器都得等待。

另一个问题是 AI 助手组件重新挂载时只保留系统入口，已经读过的普通/研发会话列表被丢掉。即使只刷新当前会话，重新进入页面仍要等待完整目录响应。

## 修改

- 已读目录按 Host connection 对象、知识范围保存在内存中；重新进入先展示它，再后台刷新。搜索结果不覆盖完整目录缓存。删除、置顶和接入会话同步更新缓存，删除前的迟到请求不能重新带回会话。连接变化后不接收旧连接的迟到目录缓存。
- 首次进入先发目录请求，再独立读取当前会话；消息识别不再额外发送一份相同的初始化详情请求，筛选变化仍单独刷新结果。
- 后台历史的恢复启动和同步投影逐次让出事件循环，新到达的目录/其他会话请求可以插入处理。异步恢复不占调度槽，悬空恢复不会挡住后面的会话。
- 只展示聊天消息的读取跳过工具摘要序列化；完整工具执行记录仍由原来的轮次投影提供。
- 缓存只用于列表展示；发送仍等待当前会话的实时读取与原有权限/运行状态校验。没有创建、取消或重新提交业务任务。

## 测量与验证

- 对本机数据的隔离副本进行只读测量：状态文件约 81 MB；已关联目录 16 项；热状态下目录首次读取约 17 ms。研发主会话副本 1421 个事件、未压缩约 4 MB，详情约 70–84 ms。这不能证明运行中的真实宿主延迟原因，但排除了把副本里的目录排序直接当成数十秒慢点。
- 新故障测试包含 40 个已加载历史，每个投影模拟 12 ms 同步工作；用下一次事件循环发起目录请求。旧代码前 8 个测试仍通过，但新测试失败，目录等待约 1926 ms。修复后目录约 1 ms 返回，40 份助手历史、原有任务和唯一消息标识均保留。
- `tests/assistant-hub-loading.mjs`：10 项通过。
- `plugin-tests/tests/assistant-hub.test.jsx`：138 项通过，新增返回页面时立即使用旧列表、慢刷新期间仍可切换会话、局部补入新目录、首次请求顺序、初始化详情去重。
- `pnpm check` 通过。全量回归日志：`/tmp/hub-fair-full.log`；压力测试旧代码对照：`/tmp/hub-fair-baseline.log`；修复压力测试：`/tmp/hub-fair-host.log`；助手界面测试：`/tmp/hub-fair-ui.log`。

本轮没有为验证而发起真实研发任务或模型请求。真实宿主当时研发任务已经结束，不能将隔离压力测试结果表述为“真实任务运行中已验收”。
