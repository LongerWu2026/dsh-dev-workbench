# 工作台助手交互设计建议

- 日期：2026-10-27。
- 状态：设计建议，尚未实现；随待办后续统一处理。
- 范围澄清：聊天发生在 DeepSeek Harness 内的工作台旁边，不是当前 Codex 聊天。
- 指令执行与性能方案见 [AI-COMMAND-EXECUTION.md](AI-COMMAND-EXECUTION.md)。

## 1. 推荐方案

在工作台插件内部增加可折叠的「工作台助手」右侧栏，提供连续对话。执行层优先复用 DSH 原生 Session、模型、工具、历史和审批。卡片 AI 操作、自由聊天、后台自动处理共用工作台业务服务。

保留工作台八个模块。工具栏增加「AI 助手」入口；助手打开时与当前内容并排，关闭后恢复内容宽度。复杂分析可在同一原生会话继续。

备选方案是底部 AI 命令栏：识别、摘要等短操作直接展示结构化结果，多轮讨论跳转原生会话。它占用空间较少，适合原生侧栏嵌入尚未验证时先落地。

## 2. 三种入口

| 入口 | 典型用途 | 行为 |
| --- | --- | --- |
| 工作台助手 | “今天先做什么”“把这个延期到周五” | 对话理解意图，按需查询和调用工作台工具 |
| 卡片 AI 按钮 | 消息识别待办、资讯分析、任务拆解 | 附上所选对象引用，在助手显示操作过程与结果 |
| 后台自动化 | 定时同步、任务提取、资讯摘要 | 按独立配置运行，落库后更新卡片；无需打开侧栏 |

输入材料第一版支持文字、链接和已采集的消息/资讯/任务引用。图片和文件识别在核实宿主上传与模型能力后扩展。

## 3. 布局与状态

- 工作台区域足够宽时采用并排侧栏，建议初始宽度 380–420px，并允许收起；具体断点依据插件可用区域决定。
- 窄窗口采用覆盖式助手或独立助手视图，保留返回原页面的位置。
- 顶部展示当前项目、会话和执行状态；输入区展示本次携带的上下文引用，允许移除。
- 切换工作台页面不重置对话。切换项目后展示对应的工作台会话；运行中的请求固定归属提交时的项目，结果不得写入后来切换的项目。
- 切换卡片不会自动提交消息，也不会每点一次就创建新会话。上下文切换须可见，发送时固定本次上下文。
- 收起助手仅隐藏入口；停止执行使用独立的停止操作，沿用宿主语义。

## 4. 上下文与会话

建议按项目维护一个可持续的工作台助手会话，无项目时使用通用工作台会话。业务状态保存项目与原生 `sessionId` 的映射，对话历史由宿主负责持久化。正式任务执行关联独立 AgentRun，必要时使用任务会话。

每次请求只传用户意图、项目 ID、选中对象 ID、可见引用和必要的时间/时区。Host 按权限读取最新业务对象，按需补充消息前后文。避免每次把整份状态与所有消息装入提示词。

会话草稿属于各自会话；跳转原生聊天时不能覆盖已有输入或自动发送。若目标会话不存在，明确创建并关联新会话。重连后从宿主恢复历史及运行状态。

## 5. 识别、提议与执行

| 用户表达/触发方式 | 默认行为 |
| --- | --- |
| “解释一下”“识别一下” | 分析或生成提议，展示结果，不据此直接改业务数据 |
| “帮我添加”“延期到周五”“标记完成” | 目标明确且通过校验后执行本地修改，返回具体结果 |
| 卡片「AI 识别」 | 生成可编辑候选，展示标题、期限、负责人和原文依据 |
| 已开启的后台自动入库 | 按配置对证据明确的事项自动入库；歧义事项进入待确认 |
| 删除、发布、迁移外部系统 | 遵守项目确认要求和宿主权限机制 |

结果采用能继续操作的卡片：任务候选、已更新任务、资讯摘要、知识条目。明确显示修改了哪个对象、哪些字段、哪些来源；工具成功并落库后才展示成功状态。失败区分模型分析失败、校验失败、写入失败，重试使用同一幂等标识。

例：消息中写“请你明天17:00前补充接口文档。压测结果也帮我确认一下”，应拆为两项；第一项期限依消息发送时间解析，第二项期限缺失时留空，保留原文证据。

## 6. 技术职责

```text
插件侧栏 / 卡片 AI 操作 / 后台自动化
                    ↓
           工作台请求与上下文适配层
                    ↓
       DSH 原生 Session / 模型 / 工具执行
                    ↓
            工作台统一业务服务
                    ↓
       数据落盘 / 来源 / 执行记录 / 版本通知
                    ↓
              页面更新与结果展示
```

助手 UI 只处理输入、引用与展示。业务权限、校验、去重和写入由 Host 服务负责。聊天工具不重复实现业务修改。前端不保存模型凭据，也不直接写状态文件。

优先使用宿主公开的会话与组合接口。若侧栏中暂不能合法复用完整原生对话界面，先使用卡片操作和原生会话跳转，不直接导入其他功能插件的内部 React 组件。

## 7. 接入依据与待验证项

2026-10-27 阅读的官方 master 文档提供了以下依据；这些依据不能替代当前安装版本的验证。

- [Web Client architecture](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/web-client.md)：会话由 Host/Client 模型和适配层持有，UI 通过 Slots 组合。
- [Session Controller](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/api/session-controller/README.md)：提供会话生命周期、提示提交、历史跟随和取消等能力。
- [Web Client Slots](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/subsystems/slots.md)：支持会话作用域和对话组合，限制跨功能运行时组件直接导入。
- [UI Workspace](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/client/ui-workspace/README.md)：提供原生会话导航和草稿准备能力。

实施前验证：安装版本及可用服务、原生对话可复用位置、侧栏绑定会话的生命周期、权限与停止行为、草稿保留、流式重连、与宿主其他侧栏的布局兼容性。

## 8. 分阶段验收

1. 修复待办清单 01–03，保证数据关联与工具执行稳定。
2. 验证原生会话适配；先实现卡片带上下文进入会话，打通识别→结果→工作台回写。
3. 实现折叠侧栏、连续对话和任务/资讯结果卡片，验证不同项目与多次请求不串上下文。
4. 复用同一业务能力接入后台自动待办与资讯处理，验证关闭侧栏后仍按配置工作。

完成标准：真实宿主里的一次消息识别、一条聊天维护指令、一次资讯摘要都可追溯到来源和写入对象，重启后关联保持一致。

## 9. 资讯自动发现：联网搜索为默认入口

用户无需逐个维护资讯网站或 RSS。复用工作台已有关注主题，支持在聊天里提出“整理最近一天的 Agent 和 RAG 资讯”，也可按配置后台运行。

建议流程：主题与时间范围 → 生成多组中英文搜索词 → DSH 联网搜索 → 选择原始发布来源 → 获取页面、核对事件及发布时间 → 合并重复事件 → 生成有引用的摘要和项目关联 → 保存到资讯卡片。

搜索结果发现与模型归纳分开处理：优先经原生会话使用 `web_search`、`web_fetch`，确保账号、模型路由与凭据上下文正确；确定性的采集部分可复用 `ctx.web` 服务。普通模型文本回答不能替代实际联网结果。RSS/Atom 作为用户有固定订阅需求时的补充入口。

当前项目的统一搜索已实现 `ctx.web.search` 路径，但资讯抓取尚未接入这条路径。官方 master 的联网工具和 DeepSeek 搜索 Provider 可复用宿主已配置的能力；当前安装版本、Provider 就绪状态和真实调用仍须验证。页面显示“联网不可用/搜索失败”时，不能伪装为成功或“没有新资讯”。

新增验收：不配置任何 RSS，在宿主联网能力已就绪的条件下，能通过一条指令或一次刷新，生成带来源与日期的资讯卡片，并支持重复执行去重。

依据：[联网能力包](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/web/README.md)、[联网工具](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/web/tool-web/README.md)、[DeepSeek 搜索 Provider](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/web/web-search-deepseek/README.md)。
